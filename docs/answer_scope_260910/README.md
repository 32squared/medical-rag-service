# 우리 RAG 답변 프롬프트, 답변 범위 기준 적용안 ('26. 9. 10)

대상 저장소: medical-rag-service (Cloud Run medical-rag-dev). 대상 파일: `rag_engine.py` 의 `_build_rag_system_prompt()`, `personal_llm_context.py` 의 원시 PHR 주입 지침 한 줄.
적용 방법: `apply_answer_scope_260910.py <repo>` 를 실행하거나 `answer_scope_260910.diff` 를 `git apply` 한다. 두 방법 모두 같은 결과이며, 적용 후 결과 프롬프트 전문은 `rendered_prompt_raw_260910.txt` 와 같다.

## 1. 왜 바꾸는가

9. 9 운영 SKIX(v16)에 물은 6분야 12턴을 9. 10 같은 케이스 PHR 로 우리 RAG(dev)에 다시 물어 답변 전문에 해석 수준을 표시했다 (`PHR_효과극대화_SKIX_vs_RAG_260910.html`).

| 항목 (턴 수, 12턴 중) | 운영 SKIX v16 | 우리 RAG dev |
|---|---|---|
| 기준 대비 서술 L1 / 항목별 추세 L2 | 1 / 2 | 2 / 7 |
| 질환 가능성 표현 L5 | 0 | 1 ("피로의 원인으로 빈혈 가능성이 시사됩니다") |
| 진료과·시기 지시 L6 | 0 | 7 ("1개월 내 가정의학과·내분비내과 진료", "유방외과에 상담 일정을 잡아") |
| 질문과 무관한 검색 문서 혼입 | 0 | 5 (스트레스 질문에 음주 갈망, 검진 질문에 흉부 CT·폐색전증) |
| 응답 시간 중앙값 | 32초 | 11초 |

RAG 가 기록을 더 깊이 읽는 장점(eGFR 하락, 역류성식도염 검진 기록, 처방 종료 상태)은 살리고, L5·L6 과 노이즈는 없애는 것이 목표다.
L5·L6·연령·성별 되묻기는 우연이 아니라 현재 RAG 프롬프트가 요구하는 문형이다.
규칙 4 "OO 가능성을 시사합니다 [N] 로만 표현", 섹션 가이드 "진료과 안내, OO과 진료를 고려 + 시점", 문진 항목 "환자 맥락: 나이·성별".

## 2. 답변 범위 기준 (운영 서비스와 같은 잣대)

해석 수준은 표현의 세기가 아니라 근거의 위치로 나눈다. 기록과 공개된 일반 기준만으로 쓸 수 있는 문장까지가 L3 이고, L4 부터 이 사람에 대한 모델의 판단이 들어간다.

| 수준 | 뜻 | 허용 문형 (v16 과 동일) | 금지 문형 |
|---|---|---|---|
| L0 기록 재현 | 기록 값을 그대로 | "알려주신 기록의 2024-06-24 혈색소는 7.8 g/dL입니다 [내 기록]" | 값만 나열하고 끝내기 |
| L1 기준 대비 분류 | 공개 참고범위 안/밖 | "공복혈당 148 mg/dL (일반 참고범위 70~99, 검사실마다 다를 수 있음)", "빈혈 범위에 해당하는 수치" | "당뇨병입니다", "빈혈입니다" |
| L2 항목별 추세 | 같은 항목의 회차 변화 | "2021년 24.2에서 2024년 26.4로 높아졌고 참고범위 위에 있습니다" | 여러 항목을 묶은 흐름 판단 |
| L3 연결·권고 재전달 | 기록된 판정·권고·재검 시기 | "기록에 6개월 후 재검 권고가 남아 있습니다", 미이행 3문장, "판정에 영향을 주었을 가능성" | 기록에 없는 새 지시 |
| L4 종합 상태 평가 | 여러 항목 묶은 판단, 개인 위험도 | 금지. 항목별 L1·L2 로 나눈다 | "대사 지표가 전반적으로 나빠지는 흐름", "복부비만 관련 대사 위험" |
| L5 질환 가능성 | 사람에게 병명 부여 | 금지. 값과 기준의 관계로 바꾼다 | "빈혈 가능성이 시사됩니다", "OO이 의심됩니다" |
| L6 진료과·시기·검사 지시 | 진료 지시 | 금지. 기록된 권고 재전달 또는 "의료진과 상담하여 확인" | "1개월 내 내분비내과 진료", "내과 진료를 고려" |

준거: 의료법 제27조, 보건복지부 비의료 건강관리서비스 가이드라인, 마이헬스케어 프롬프트 규칙 확정본(C-5 질환명·진단·처방 금지, C-7 성별·나이 추정 금지, C-10·C-11 응급 발동 근거, C-13·C-14 규칙 지속, C-17 값 나열 금지, C-18 면책 반복 금지, P-1·P-3 판정과 권고 각각·재검 시기 재전달, P-8·P-9 상병명 창작·결과표 밖 내용 금지), 8. 28 개선안의 해석 계층·추세 서술·재검 권고 재이행 조항, 법무 검토 요청서의 v16 허용 문형.

주의할 결정 지점. 확정본 C-6 은 "진료과 안내는 하되 진단을 근거로 대지 않는다"로 진료과 안내를 필요한 기능으로 본다. 반면 운영 v16 과 8. 31 개선 요청서는 진료과·의료기관 지정을 금지하고, 어디까지 허용할지는 법무 질의 4항(진료 시기·검사·진료과 안내 형식)의 회신 대상이다. 이 적용안은 회신 전까지 운영과 같은 금지 쪽에 맞췄다. 회신이 허용으로 오면 규칙 9-L6 한 항목을 C-6 문형("증상과 확인이 필요한 사항을 근거로 OO과 안내")으로 바꾸면 된다.

## 4. 프롬프트 밖에서 함께 바꿀 것 (RAG 세션 판단)

1. 응급 게이트 G3. `personal_llm_context.build_raw_context()` 는 응급 의도면 PHR 을 아예 주입하지 않는다. 그래서 숨참·어지럼 후속 질문에서 혈색소 7.8 기록이 사라진다(운영 SKIX 도 같은 약점). 새 플래그(예: `PERSONAL_RAW_IN_EMERGENCY`, 기본 off)로 응급에서도 주입하고, 규칙 6 의 "응급 안내 뒤 기록 1~2문장 연결"이 그 사용법이다.
2. 참고범위 근거. 규칙 1 은 모든 의학적 주장에 [N] 을 요구하는데, 참고범위는 검색 청크에 없을 때가 많다. 국가건강검진 판정 기준(참고범위) 문서를 KB 에 넣어 인용 가능하게 하거나, PHR 주입 시 고정 청크로 함께 넣는다. 그 전까지는 예외 조항 (d)의 [일반 기준] 표기로 버틴다.
3. 검색 노이즈. 규칙 10 은 보조 수단이다. 재랭킹 점수 하한이나 질문과 청크의 주제 일치 확인을 코드에서 걸어야 음주·폐색전증 같은 청크가 프롬프트에 들어오지 않는다.
4. 버전 표식. STOP 이벤트 메타에 `prompt_version: "answer-scope-260910"` 을 실으면 재측정 때 어느 프롬프트의 답인지 구분된다(사용자 노출 없음).
5. 문체. 확정본 C-19(이모지·목록 지양, 문장 40자 안팎)는 이번 범위에 넣지 않았다. 답변 형식은 RAG 팀 결정 사항이라 별도 논의.
