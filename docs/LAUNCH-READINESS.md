# 출시 전 체크리스트 (Launch Readiness)

> **현재 단계: 출시 전 검토용 프로토타입** — 점진적으로 완성도를 높이는 중.
> 이 문서는 *실제 사용자 출시* 전에 반드시 끝내야 할 업무를 기록한다.
> **"테스트 통과(그린)"는 "출시 가능"과 다르다.** 테스트는 코드가 설계대로 도는지 검증할 뿐,
> 의료적 정확성·법적 충분성·실사용 안전을 보장하지 않는다.

## 범례
- 🔴 **BLOCKER** — 미완 시 출시 불가(법적/안전 노출)
- 🟠 출시 전 필수
- 🟡 출시 직후 단기
- 분류: ⚖️법무 · 🏥의료 · 🛠️엔지니어링 · ☁️인프라 · 🔐보안 · 📈운영

## 0. 이미 갖춰진 것 (기준선 — 아래는 이 위에 얹는 일)

경계선 설계(원시값 LLM 미투입)·밴드 중립라벨(I12)·관련성 게이트(과노출 차단)·응급 억제(I7)·
C20/C21 백스톱·가드레일/면책·비식별 이벤트(E2)·개선루프 골든셋 게이트 **설계**·방향2 6게이트(기본 off).
→ 이는 **안전 스캐폴딩(엔지니어링 설계)**이며, 법적 충족·의료 검증·운영 등급은 아래에서 별도로 채운다.

---

## A. 법적·규제 🔴 ⚖️
- **A1 의료법 27조 검토** — 변호사 자문으로 "어디까지 건강정보 제공(합법) / 어디부터 의료행위(면허 필요)"를 확정. **밴드 라벨·개인 평가가 의료행위로 해석될 리스크** 평가.
  - 현재: 미착수. `docs/plan/17`은 *엔지니어링 설계*일 뿐 법률의견 아님.
  - 완료 정의: 법률의견서 + "우리 서비스의 의료행위 비해당 범위" 제품 정의 확정.
- **A2 규제 확인 / 샌드박스** — 식약처 SaMD(소프트웨어 의료기기) 해당 여부, 규제 샌드박스 검토.
  - 완료 정의: 해당 여부 공식 회신.
- **A3 표시·면책 법적 검토** — 면책/고지 문구가 법적으로 충분한지 검토.

## B. 개인정보·동의 🔴 ⚖️🛠️
- **B1 민감정보 동의 시스템** — 건강정보 처리 **별도 명시 동의** UI + 동의 원장(consent_ledger), 철회·이력.
  - 현재: 코드 게이트(`personal_consent`)만 존재, **실제 동의 캡처 없음**. (migration 017+ 예약)
  - 완료 정의: 동의 흐름 + 철회 + 기록 + 미동의 시 개인화 비활성.
- **B2 국외이전 동의** — 국외 LLM(OpenAI 등) 사용 시 별도 동의·고지.
  - 현재: 코드 ack(`ALLOW_CROSS_BORDER_PERSONAL`)만. **실제 동의 없음** → 켜면 위반 소지.
- **B3 처리방침·위탁** — 개인정보처리방침, 처리위탁(LLM/클라우드) 계약·고지.
- **B4 보유·파기·접근통제** — `rag_queries`가 **질의 원문(query_text)을 저장**한다. 보유기간·파기·접근권한 정책 수립.

## C. 인프라·국외이전 🟠 ☁️
- **C1 국내 LLM 경로** — self-hosted/국내 모델을 `llm_providers`에 등록하고 **개인신호 트래픽을 국내로 라우팅** → 국외이전 자체 제거. (방향2를 안전하게 켜는 선결, `DOMESTIC_LLM_PROVIDERS`)
- **C2 데이터 국내 저장** — DB·로그·백업 리전 국내.

## D. 의료 콘텐츠 품질 🔴 🏥
- **D1 KB 의료진 검수** — 답변 근거(KB)의 정확성·최신성·커버리지를 **의료진이 검수·승인**.
  - 현재: dev KB가 기본 질의("두통")에도 *근거부족* 반환 — **커버리지 부족, 콘텐츠 미검증**.
  - 완료 정의: 핵심 토픽 커버 + 의료진 승인 프로세스 가동.
- **D2 밴드 기준 출처·검증** — `seed_reference_ranges`의 임상 기준(학회 가이드라인) 출처·버전·정확성 의료진 검증.
- **D3 골든셋 안전 회귀 연결** — 거짓안심0·진단단정0·과노출0 + **방향2 개인맥락 주입 시 안전** 케이스를 **배포 게이트(E3)에 실제 연결**(현재는 일부 골든셋만, 자동 차단 미배선).

## E. 데이터 영속·보안 🟠 🔐🛠️
- **E1 영속 마이그레이션(017+)** — `personal_record`/`personal_record_sensitive`/`consent_ledger`/`personal_measurement` (현재 in-memory 시드).
- **E2 암호화·최소권한** — 민감 PHR(약물·진단명) 암호화, 접근 최소권한, 감사로그.
- **E3 운영 인증 설정** — trust secret/Bearer 실제 운영값, 비밀관리(시크릿 매니저).

## F. 품질·관측 🟡 📈
- **F1 모니터링 연결** — `analytics_events` → BI(Metabase/Grafana) 실제 대시보드 + 이상 알림.
- **F2 사람 검수 큐(E5) 운영** — 피드백→개선 루프 실제 가동.

## G. 운영 🟠 📈
- **G1 운영등급 배포** — dev → prod 분리, SLA, 장애대응.
- **G2 안전 사고대응** — 응급 오탐/누락 등 이상징후 모니터링·대응 절차.
