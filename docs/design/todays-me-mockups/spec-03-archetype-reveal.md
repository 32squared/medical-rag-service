## 1. 화면 목적과 진입·이탈 경로

### 1-1. 목적

오늘 완료한 트랙 조합을 **캐릭터 1개로 압축해 보여주는 보상 화면**이다. 수치·밴드·구간을 말하지 않고 **오늘 한 행동만** 말한다. 다음 행동을 들이밀지 않는다(정본 §1-7 "다음 행동 안내 (없음)" 원칙 계승).

### 1-2. 진입 경로

| # | 경로 | 조건 | 연출 |
|---|---|---|---|
| A | 화면 2 하단 CTA "오늘의 캐릭터 만나기" 탭 | 완료 트랙 ≥ 1 · 밴드 ≠ 경고 | 3단계 리빌 **실행** |
| B | 같은 날 재진입 (A 또는 도감에서 다시 열기) | `reveal_seen_at`이 오늘 | 연출 **생략**, 결과만 |
| C | 도감(컬렉션) 화면에서 지난 날 슬롯 탭 | 그날 아키타입 존재 | 연출 생략, 과거 결과 뷰. **카드 재생성 불허**(교차검수 C5 · 브리프 §4) → T3-16 미노출. 카드 재편집은 당일 00:10까지 |

**이탈 시 문구 규칙**: "정말 나가시겠어요?", "카드를 안 만들면 사라져요", "조금만 더 볼까요?" 류 **전부 금지**(정본 §0-2 금칙 4 무비난). 결과는 이미 서버에 저장돼 있으므로 소실 경고 자체가 성립하지 않는다. 필요 시 중립 캡션 T3-17b "결과는 저장돼 있어요"(11자)만 1줄 허용.

### 1-4. 자동 팝업이 아닌 이유 (정본 안티골)

정본 §0-2 금칙 6은 **전면 축하 모달(자동 팝업)** 을 안티골로 명시하고, D1 첫 성공 1회만 예외로 둔다. 브리프 §4도 "리빌 화면은 사용자가 버튼을 눌러 여는 화면이다. 자동 팝업·전면 모달 아님"으로 못 박는다. 따라서:

- 체크인 완료 직후 이 화면을 **자동으로 띄우지 않는다.** 화면 2까지 사용자가 스스로 이동하고, 하단 CTA를 눌러야 열린다.
- 푸시·위젯·딥링크에서 이 화면으로 **직행하지 않는다.** 화면 1(오늘의 체크인)으로 보낸다.
- 리빌이 준비됐다는 사실은 화면 2 CTA 옆 **점 표시**로만 알린다. 숫자 배지 금지(금칙 6 "미완료 숫자 배지" 확장 적용).

### 1-5. D1 첫 성공 예외와 이 화면의 관계

정본 §1-6은 D1 완료 직후 전면 축하 1회를 예외로 허용하고, 그 카피는 "**첫 기록이 남았어요.** 이제 알림 시각만 정하면 끝이에요."다. 이 모달은 **알림 시각 설정으로 이어지는 온보딩 모달**이며, 리빌 화면과 별개다.

| 항목 | D1 전면 축하 모달 (정본 §1-6) | 이 화면 (T3) |
|---|---|---|
| 소유 | 루틴 온보딩 | 재미 레이어 |
| 트리거 | D1 첫 완료 직후 자동 1회 | 항상 사용자 탭 |
| 다음 행동 | 알림 시각 시트 | 카드 만들기(선택) |
| 겹침 | — | **겹쳐 띄우지 않는다** |

D1 규칙: 축하 모달 → 알림 시각 시트 → H2 순으로 정본 흐름을 끝낸 뒤, 화면 2 CTA에 힌트 T3-18b "처음 만나는 캐릭터가 있어요"(15자)를 **1회만** 표시한다. **가정:** 이 힌트는 D1에 한정하고 D2 이후에는 노출하지 않는다.

### 3-1. 경고 밴드 — 진입점 자체를 노출하지 않는다

정본 §0-3은 경고 밴드에서 **스트릭·배지·레벨 문구 전부 숨김**을, 갱신된 브리프 §4는 **캐릭터·카드·도감 진입점 자체를 노출하지 않는다**를 규정한다(교차검수 **C7 판정**). 원칙은 **진입점 미노출**이며, 치환 화면 T3-W는 **딥링크·푸시·구버전 캐시 등 잔존 경로의 방어용으로만** 유지한다 — 정상 경로에서는 T3-W에 도달할 수 없다. 따라서 경고 밴드에서는:

| 레이어 | 처리 |
|---|---|
| 화면 2 CTA | 렌더하지 않는다. 자리에 "이번 주 기록 보기"(기록형 · 브리프 §4) |
| 이 화면 | **진입 경로 없음.** 캐릭터·태그·희귀도·컬렉션·카드 만들기 전부 미생성 |
| 도감 | **진입점 숨김 — 교차검수 Q5 채택.** 과거에 받은 캐릭터도 경고 기간에는 노출하지 않고, 밴드 복귀 시 다시 보인다. 데이터는 삭제하지 않는다 |

## 4. 인터랙션·모션

### 4-1. 3단계 리빌 타임라인 (총 2,300ms ≤ 상한 2,500ms)

| 단계 | 시작 | 지속 | 누적 | 이징 | 요소 · 변화 |
|---|---|---|---|---|---|
| **1 어두워짐** | 0 | 320 | 320 | `cubic-bezier(0.4, 0, 1, 1)` (ease-in) | T3-19 스크림 α 0→0.28 · T3-02 장식 α 1→0.35 · T3-05/06 카드 스택 뒷면 상태로 대기(rotateY 180°, scale 0.92) |
| **2 원소 3개가 모임** | 300 | 900 | 1,200 | `cubic-bezier(0.34, 1.3, 0.64, 1)` (약한 오버슈트) | T3-20 물방울(좌상 −40,120) · 번개(우상 430,150) · 달(우하 420,520)이 중앙(195,270)으로 이동 + rotate ±24°→0 · stagger 0 / 90 / 180ms · 각 도착 직후 60ms scale 1→1.12→1 |
| **2b 수렴** | 1,200 | 100 | 1,300 | `linear` | 중앙 흰 원 α 0→0.9→0, r 0→96px · 원소 3개 α→0 |
| **3 카드 플립** | 1,300 | 700 | 2,000 | `cubic-bezier(0.2, 0.8, 0.2, 1)` | 카드 스택 `rotateY` 180°→0°, `perspective 1000px`, scale 0.92→1 · T3-19 스크림 α 0.28→0 · 뒤 카드 rotate 0→6°, 중간 카드 0→−4° (지연 120ms) · T3-07 캐릭터 α 0→1 (플립 60% 지점부터) |
| **4 텍스트 등장** | 1,900 | 400 | 2,300 | `cubic-bezier(0.16, 1, 0.3, 1)` (ease-out) | T3-08 → T3-09/10 → T3-11 → T3-12 → T3-13~15 순서, 각 y +12→0 / α 0→1, stagger 60ms |

- **완료 트랙이 1~2개일 때**: 2단계에 등장하는 원소도 1~2개다. 빠진 트랙 자리를 회색 원소·빈 슬롯으로 표시하지 **않는다**(정본 §0-1 "쉬어간 날" 원칙 — 안 한 것을 시각화하지 않음). 원소가 1개면 2단계 지속을 900 → **600ms**로 줄여 총 2,000ms.
- 프레임 예산: 60fps 기준 `transform` / `opacity`만 애니메이트. `filter`·`box-shadow` 애니메이션 금지.

### 4-2. 햅틱·사운드

| 항목 | 정책 |
|---|---|
| 햅틱 | **1회만.** 3단계 카드 플립 시작 시점(1,300ms)에 medium impact. iOS `UIImpactFeedbackGenerator(.medium)` / Android `EFFECT_TICK` 강도 중 (**가정:** 세기 매핑) |
| 햅틱 추가 발생 | 태그·컬렉션·CTA 탭에는 햅틱 없음. 건너뛰기 시 햅틱 없음 |
| 사운드 | **기본 꺼짐.** 설정 > 소리에서 켤 수 있음. 켠 경우에도 3단계 1회, 길이 ≤600ms, 무음 스위치·미디어 볼륨 존중 |
| 시스템 설정 | 기기 햅틱 끄기 / 저전력 모드에서는 햅틱 생략 |

### 5-3. 희귀도 계산 규칙

**정의**

```
분모 D = 이번 달 1일 00:00 ~ 오늘까지, 리빌을 1회 이상 받은 활성 사용자 수 (사용자 단위 중복 제거)
분자 N = 그중 이 아키타입을 1회 이상 받은 사용자 수
rarity_pct = round(N / D × 100)
```

- **일(day) 단위가 아니라 사용자 단위**로 센다. 한 사람이 같은 캐릭터를 5번 받아도 1로 센다.
- 밴드 경고 사용자는 리빌이 생성되지 않으므로 분모·분자 모두에서 자연 제외된다.
- 배치 갱신 주기 **가정:** 1일 1회(KST 04:00). 당일 데이터는 전날까지의 집계를 쓴다.

**표시 규칙**

| 조건 | 표시 |
|---|---|
| D ≥ 100 이고 1 ≤ pct ≤ 99 | T3-12 **"이번 달 이 캐릭터 만난 사람 `{pct}`%"**(20자 · 교차검수 **C4 채택**) |
| pct < 1 (반올림 0) | "이번 달 이 캐릭터 만난 사람 1% 미만" |
| **D < 100** (교차검수 **C3 판정** — 표본 하한 100명) | **희귀도 줄을 숨기고, 그 자리는 로어(T3-10)가 대신한다.** 대체 문구를 만들지 않는다(화면 4 S4 방식과 통일) |
| 통계 배치 미갱신 · API 실패 · 오프라인 | 위와 동일 — 줄을 숨기고 아래 요소를 끌어올린다 |

**금칙**

- 순위·상위 n%·"희귀"·"레어/전설" 등급·"드물어요"·"흔해요" 표현 금지 → **우열 프레임 금지**(정본 §0-2 금칙 6 랭킹·리더보드 확장 적용).
- 다른 사용자와의 직접 비교("당신보다 많이 한 사람 n명") 금지.
- 가장 흔한 아키타입(예 62%)도 **같은 문장 틀**을 쓴다. 문구를 바꿔 우열을 암시하지 않는다.
- 희귀도를 근거로 한 보상·수집 유도 문구("이 캐릭터를 모으면…") 금지.

## 7. "왜 이 캐릭터?" 태그 생성 규칙

### 7-1. 원칙

1. **오늘 완료한 트랙만** 태그가 된다. 완료 트랙 수 = 태그 수(1~3개). 3개 미만일 때 빈 자리를 만들지 않는다.
2. **안 한 트랙은 언급하지 않는다.** "물은 못 마셨지만", "활동 기록 없음", 회색 비활성 태그 전부 금지(정본 §0-1·§0-2 금칙 4).
3. **행동 지표만** 담는다. 검진 수치·밴드·구간·연속 일수·목표 대비 달성률 금지.
4. **평가·감탄을 붙이지 않는다.** "6,400걸음이나!", "훌륭해요" 금지 → 값만 적는다.
5. 순서 고정: **식이 → 활동 → 리듬** (완료한 것만 남기고 순서 유지).

### 7-2. 형식

```
[원소 점 8px #원소색] + 공백 6px + {라벨}{값}{단위}
```
- 텍스트 **12자 이내**(**가정:** 알약 폭 기준. 브리프 §2 버튼 라벨 12자를 준용).
- 라벨은 값만으로 뜻이 통하면 생략한다(예: `6,400걸음`에는 "활동" 라벨을 붙이지 않는다).
- 천 단위 콤마 사용. 단위는 붙여 쓴다.

### 7-3. 트랙별 태그 템플릿

|---|---|---|---|---|
| 식이 기록 | #4C86F0 | `물 {n}컵` | `기록 {n}회` | `기록 남김` |
