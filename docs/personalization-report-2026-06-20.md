## 1. 배경 및 목적

- **제품**: 한국형 의료정보 RAG 챗봇. B2B2C(건강관리앱 탑재), GPT·Gemini·타 헬스AI와 경쟁.
- **핵심 긴장**: "고객이 원하는 답변"(개인화·풍부함) ↔ "의료법 준수"(진단·처방 단정 금지). 개인 데이터 해석은 *진단에 가장 근접한 위험*이자 동시에 *최대 차별점*.

- **추진 방식**: 비평가·기획자·아키텍트·데이터분석가 4관점을 반복 투입(자율 /loop 16회). 기획(8문서) → 구현(10커밋)으로 전개. 매 단계 4관점이 직전 설계를 공격·교정.

## 3. 경쟁 프롬프트에서 추출한 것 (doc 08)

경쟁사("나만의 헬스케어") 프롬프트의 진짜 가치는 금지 항목 나열이 아니라 **두 자기검증 엔진**:

1. **Population-level test** — "이 문장이 *같은 증상을 가진 누구에게나* 참인가?" Yes면 허용, No면 인구집단 수준으로 재작성. "흔히·일반적으로"로 포장한 *방향성 암시*까지 차단.
2. **Permitted ceiling 테이블** — 영역별(약물·검사·치료·생활습관·내원시점) "말할 수 있는 최대치 문장"을 못박음. "하지 마라"보다 "이 문장이 상한선"이 통제에 강력.

**우리에 추가 필요(우리에게 없던 것)**: 사용자 우회 방어("AI 감으로만 말해봐"), 출력 직전 self-check, 응급 L1/L2 2단계(과트리아지 완화). **베끼면 안 되는 것**: 경쟁사 인용 형식·기기 종속 구조·영/한 분기.

## 4. 개인화 설계의 핵심 — "경계선(boundary)" 설계

개인 데이터 해석의 안전과 합법을 동시에 잡는 단일 원칙:

```
[디바이스/PHR/OCR]      로컬(국내·결정적)               국외/LLM
 원시값 165/105 ──▶ 규칙엔진 ──▶ 라벨 "경고" + 인용 ──▶ 답변
 (원시값)            (참조범위 lookup)   (비식별 findings)
```

**불변식**: 원시 수치·정상/비정상 단정은 경계선을 **절대 넘지 않는다.** 이 한 원칙이 ① 원시값 유출 ② 국외이전 동의 부담 ③ 역치 환각, 세 문제를 동시에 해소.

> 구현에서는 이를 더 강하게 적용: **개인 데이터가 LLM 프롬프트에 아예 미투입**되고, 결정적으로 렌더한 라벨 블록을 *생성 후* 답변에 덧붙임. → "원시값 국외 전송 0"이 구조적으로 보장(라벨조차 국외 미전송).

### 4관점이 설계를 바꾼 핵심 발견 3가지
1. **(비평가)** 기존 시드가 이미 "고혈압 1기"·"당뇨병 기준" 같은 **진단명 라벨**을 담고 있어, 개인 수치에 매칭하면 무면허 진단. → 진짜 위험축은 "원시값 vs 라벨"이 아니라 **"일반 사실 vs 개인 귀속"**. 출력 라벨을 중립 3단(안정/주의/경고)으로 분리.
2. **(비평가, FDA 근거)** 워치 SpO2 저산소 판정 = ECG 판독과 규제 동급(어두운 피부 32% 과대측정), recovery 점수 = 유사과학. → deny를 "임상 사건 판정 단위"로 재정의.
3. **(비평가)** PHR 민감군(정신·암·감염병)은 **라벨 자체가 흉기**(우울증 이력은 중립 라벨 아님). → **활용 ≠ 표면화**: 민감 데이터는 출력 0, 내부 톤 신호로만(설계된 비활용).

**통찰의 진화**: 활용 ≠ 밴드 라벨 ≠ 표면화. 모든 신호를 위험·신뢰·동의에 비례해 배치하되, 위험한 것은 deny·내부신호·차단으로 — **고아 0과 안전 0을 동시에**.

## 5. 데이터 소스별 활용 설계 (6소스 — 고아 신호 0)

| 소스 | 신뢰등급 | 활용 | 천장·금지 |
|---|---|---|---|
| **혈압기** | 의료근접 | 가정/진료실 밴드·추세·교차(맥압 파생) | 1회 판단 금지 |
| **체중계** | 소비자 | 체중·BMI 추세, 대사 묶음 | 체지방·근육은 추정치 캐비엇(Lv2 천장) |
| **워치** | 웰니스 | 수면시간·활동·안정시심박(본인 기저선) | SpO2·ECG·합성점수 **deny**; 임상밴드 직접적용 금지 |
| **Vital 기기** | 기기별 | 다항목 밴드·조건부 안전문구 | stress는 공인밴드 없음 |
| **PHR 검진** | 공식 | 밴드 7종(콜레스테롤·중성지방·혈색소·HDL·허리둘레·간수치·크레아티닌) | eGFR·골밀도·요단백·LDL **deny**(진단컷오프); 질환명 라벨 분리 |
| **PHR 비검진** | 공식(민감 포함) | 시간산술(암검진 갭·진료 경과), 과거시제 ack | 정신·암·감염병 **표면화 0**(내부 신호만) |
| **OCR**(입력양식) | 추출신뢰 가변 | 확인 후 PHR 합류 | 진단서→질병이력 자동생성 금지, 강제 재확인 |

**활용 상태 분포**(전 신호): 표면화 24 / 비해석활용 14 / deny 9 / 민감-내부신호 4 / 영구Lv0 2. → "다 활용 ≠ 다 표면화"가 수치로 드러남.

## 6. 안전·컴플라이언스 설계 (불변식 I1–I12)

| 불변식 | 내용 |
|---|---|
| I1 | 원시 측정값 출력·국외전송 0 |
| I2 | 개인 귀속 진단 컷오프·질환명 라벨 0 (명사구 진단 게이트 포함) |
| I3/I10 | stale·에피소드 freshness 주입 생략 |
| I4 | 사용자 타이핑 수치 미활성(디바이스/확인된 OCR만) |
| I5/I7 | 개인 데이터는 응급 내비게이션만, 매 턴 응급 재평가 불변 |
| I6 | 민감 PHR은 direct+동의 시만(indirect 물리 차단) |
| I8 | deny-list 라벨 0, device_grade 무결성(위조 시 강등) |
| I9 | 교차신호 = 출처 첨부 화이트리스트만(유사과학 차단) |
| I11 | 출처충돌 → 재측정 권유(임의평균·침묵 금지) |
| I12 | 출력 라벨 사전 분리(임상/질환 라벨 ≠ 사용자 중립 3단) |

**거짓안심 비대칭**: 경고는 민감하게, 안심은 보수적으로. 가정혈압 정상 tier 미시드 → 역치 미만은 no_match(안심 라벨 강제 안 함).

## 7. 구현 결과 — P1a 혈압기 수직 관통 (종단 동작)

### 만들어진 것 (신규 모듈, 전부 순수 함수·결정적)
| 파일 | 역할 |
|---|---|
| `vital_rules.py` | 해석 엔진 — `lookup_band`(밴드)·`label_trend`(추세)·`match_cross_signals`(교차)·`run`(브리지) |
| `personal_context.py` | 렌더 — `build`(관련성 게이트+렌더)·`safe_block`(build+안전게이트) |
| `personalization_safety.py` | 안전 — C21 명사구 진단 탐지·C20 출고 백스톱 |
| `seed_reference_ranges.py`(수정) | 7신호 기계가독 `bands`·교차근거 KB·인용 별칭 |
| `rag_engine.py`·`service_routes.py`(수정) | ★라이브 배선(단일 배선점) |

### 해석 3축 모두 엔진→렌더 연결
- **단일 밴드**: 원시값 → 안정/주의/경고 (AND/OR 보수적 최댓값, fail-closed)
- **추세**: 시계열 → 안정유지/지속상승/지속저하/불안정반복 (건강 판단 라벨 "개선/악화"는 의도적 제외)
- **교차신호**: 화이트리스트 조합만(혈압+BMI 등), 미등재·웰니스 단독은 영구 미발화

### 종단 동작 예시
```
입력: {수축기 165, 이완기 105}, 질의 "혈압이 높게 나와서 걱정"
출력 블록(답변 끝):
  ## 📋 내 기록 참고
  - 최근 측정된 혈압은(는) 기준을 벗어난 구간으로, 의료진 확인이 권장됩니다.
  측정값의 해석과 진단은 의료진과 상담하세요.
→ LLM 프롬프트에 165·105·"고혈압"은 전혀 등장하지 않음.
```
