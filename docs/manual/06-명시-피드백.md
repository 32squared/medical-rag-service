# 06. 명시 피드백 (👍/👎)

답변에 대한 사용자 명시 피드백을 받아 적재하고, 비식별 집계 이벤트를 함께 남긴다.

- 코드: [`rag_routes.py`](../../rag_routes.py) `_rag_feedback`, [`rag_db.py`](../../rag_db.py) `record_response_feedback`
- 스키마: `migrations/016_response_feedback.sql`
- 테스트: `tests/test_response_feedback.py`

## 엔드포인트

```
POST /api/rag/feedback
Content-Type: application/json

{
  "rag_query_id": "rq-...",     // 필수 — 대상 답변(STOP.rag_query_id)
  "rating": "up" | "down",       // 필수
  "reason_code": "helpful",      // 선택 — 비식별 코드(원문 아님)
  "conversation_id": "c-..."     // 선택
}
```

응답: `{"status":"success","feedback_id":"..."}` (검증 실패 → 400, 저장 실패 → 500)

- `rating`은 `up`/`down`만 허용. `rag_query_id` 누락 → 400.
- **코멘트 자유텍스트는 받지도 저장하지도 않는다**(비식별). `reason_code`는 짧은 코드만.
- 인증은 선택(있으면 user_id 기록).

## 데이터 레이어

```python
rag_db.record_response_feedback(
    rag_query_id, rating, *,
    conversation_id=None, user_id=None, reason_code=None,
) -> feedback_id | None
```

1. `response_feedback`에 1행 적재(rating·reason_code만).
2. 비식별 `thumbs_up`/`thumbs_down` 이벤트를 `analytics_events`로 emit(집계용).
3. 유효성 위반(`rating` 비정상·`rag_query_id` 공백) → None.

## response_feedback 컬럼

| 컬럼 | 설명 |
|---|---|
| id | uuid |
| rag_query_id | 대상 답변(rag_queries.id) |
| conversation_id / user_id | 조인 키(옵션) |
| rating | `up` / `down` |
| reason_code | 비식별 코드(inaccurate·unhelpful·too_long 등) |
| created_at | ISO 타임스탬프 |

## 개선 루프 연결

명시 피드백은 개선 백로그의 입력 신호(B 레인)다.
- 👎 + 거절수요(05 E4) → KB 확장·표현 개선 1급 입력.
- 집계는 `analytics_events`(thumbs_up/down)로, 사람 검수(E5)를 거쳐 개선 항목화.
- 어떤 변경도 **골든셋 게이트(E3)** 통과 시에만 배포(안전 회귀 0).
