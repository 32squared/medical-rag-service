## 0. 한 줄 정의

**의료법(무면허 의료행위 27조) 경계 안에서** 개인 건강 데이터를 활용하는 **한국어 의료정보 RAG**. 진단·처방 **단정 0**, 거절 대신 **내비게이션**(어디로 가야 하나)으로 욕구를 충족. B2B2C(건강관리 앱에 임베드, GPT/Gemini와 경쟁). 파트너 대화 플랫폼(**wraith**)에 SSE로 연결.

핵심 설계 = **경계선 설계(boundary design)**: 원시 측정값은 결정적 로컬 엔진이 해석해 **중립 라벨**로만 LLM/국외에 넘긴다.

## 1. 시스템 아키텍처 (현행)

```
사용자 질의 + 개인화 입력(agent_input_field_to_value: 혈압/체중/Vital/공기질/PHR)
   │
   ▼  service_routes._service_run_graph  (wraith 호환 SSE 엔드포인트)
   │     ├─ vital_input.parse_agent_inputs → vital_rules.run/run_trends + env_rules → personal_findings
   │     └─ personal_consent 파싱
   ▼
rag_engine.generate_response  ───────────────────────────────────────────┐
   1) medical_classifier 분류(intent·도메인) + 멀티턴 재작성(followup_rewriter)
   2) hybrid_search(BM25+벡터, top_k=5) → retrieval_router 근거게이트(SUFFICIENT/WEAK/INSUFFICIENT)
   3) [방향2] personal_llm_context.build_llm_context → 비식별 밴드라벨을 system_prompt 주입(6게이트, 기본 off)
   4) llm_router.stream_chat (gpt-5.4-mini, reasoning=minimal) → GENERATION 스트리밍
   5) 가드레일 후처리: analyzer 재분석 → (위반 시 재생성) → 인용검증 → 면책 부착
   6) [개인화 후append] personal_context.safe_block → 답변 끝에 '내 기록' 블록(응급 아닐 때)
   7) 인용 추출 + citation_verifier(shadow) + grounding(shadow)
   8) rag_queries 저장 → STOP (감사·검수·analytics는 백그라운드 스레드)
   └────────────────────────────────────────────────────────────────────┘
   │  SSE 이벤트: INFO / EVIDENCE_CHECK / GENERATION / STOP / ERROR
   ▼  wraith_sse_adapter  (우리 이벤트 → wraith Run-Graph 형식 변환)
   ▼
클라이언트(파트너 앱 / persona_test_server 뷰어)
   └─▶ analytics_events(비식별 개선루프) · response_feedback(👍/👎)
```

**개인화 결합은 2경로** (둘 다 원시값 미투입):
- **경로①(기본·항상)**: 생성 *후* `personal_context.safe_block`을 답변에 후append(결정적·로컬, LLM 미경유).
- **경로②(방향2·옵트인)**: 비식별 **밴드 라벨**을 LLM system_prompt에 주입(6게이트 fail-closed, 기본 off).

## 3. 기능별 매뉴얼

### A. RAG 생성 파이프라인 — `rag_engine.generate_response`  → [04](04-RAG-생성-파이프라인.md)
- **4종 종료 경로**: 정상 `answer_shown` / 근거부족 `insufficient_evidence`(거절→내비게이션) / 응급 `emergency_redirect`(119·응급실, 개인화 억제) / 트리아지 `triage_clarify`.
- **근거 게이트**(retrieval_router): top1 점수·관련 청크 수·토픽 매칭으로 SUFFICIENT/WEAK/INSUFFICIENT 판정. `RETRIEVAL_GATE_ENFORCE`(기본 false)면 INSUFFICIENT라도 생성.
- **가드레일 후처리**: `analyzer.ComplianceAnalyzer` 재분석 → CRITICAL 차단 / HIGH 1회 재생성 / 오탐 필터(`RAG_GUARDRAIL_FP_FILTER`). 면책 상·하단 자동 부착, 동적 섹션 헤더.
- **인용**: 본문 `[n]` → 청크 매핑. `citation_verifier`(coverage·unsupported)와 `check_citation_grounding`(어휘 겹침)은 **shadow**(로그·검수 신호, 답변 무변경).

### B. 검색 / 근거 — `rag_engine.hybrid_search`·`retrieval_router`·KB
- BM25(한국어 tsvector) + 벡터 임베딩 융합, top_k=5. 출처별 `evidence_level` 티어링(공신력순).
- KB 출처: 질병청·식약처·응급의료포털·법령센터·공인 참조범위 등. dev는 기본 질의에 근거부족 잦음(KB 의료검수 = 출시 블로커 D).

### C. 멀티턴 — `followup_rewriter`·`conversation_context`·순차 문진  → [06 plan](../plan/06-multiturn-design.md)
- **후속 재작성**: 짧은 후속 질의를 직전 주제로 carry-forward(검색 단계에서 재작성). 응급이면 재작성 안 함(안전).
- **비식별 컨텍스트**: 증상키·intent·진료과만 저장(원문 미저장). 멀티턴 감사(migration 013).
- **순차 문진(되묻기)**: 간단히 물으면 **답변 먼저** → 그 답변을 바탕으로 **한 번에 한 질문**씩 선택지를 제시(Claude Code 인풋 방식). `followups.clarify`가 토픽별 질문+선택지 생성. 뷰어가 버튼으로 렌더, 다 모이면 "원질의 / 문진: …"로 정밀 재안내.

### D. 개인화 해석 엔진 — `vital_rules`·`env_rules`·`vital_input`  → [01](01-개인화-해석엔진.md)
**4축 해석(원시값 노출 0):**
1. **밴드** `vital_rules.run/lookup_band` — 혈압·산소·체온·심박·BMI. AND/OR 보수적-최대, fail-closed, 중립 3단 라벨.
2. **추세** `run_trends/label_trend` — 지속상승/저하/불안정만(개선·악화 같은 건강판단 금지). 안정·표본부족이면 미발화.
3. **환경** `env_rules.air_quality_finding` — 나쁨→주의/매우나쁨→경고, 비인과 환기 권유.
4. **교차신호** `match_cross_signals` — I9 화이트리스트(혈압+BMI 대사묶음 등), fail-closed.

### E. 개인화 결합·주입 — `personal_context`·`personalization_safety`·`personal_llm_context`  → [02](02-개인화-주입과-안전경계.md)
- **경로① safe_block**(기본): 관련성 게이트 통과 finding → 밴드별 행동 안내(`_GUIDANCE`: 경고=재측정+진료+적신호, 주의=재측정+관리, 안정=없음) → C20 백스톱 → 답변 끝 결합. 2자리+숫자 금지(119 대신 '응급실'), 질환명 0.
- **경로② 방향2 LLM 주입**(`personal_llm_context.build_llm_context`, 옵트인): 비식별 밴드 라벨을 system_prompt에 주입. **6게이트 fail-closed** — G1 `PERSONAL_SIGNAL_TO_LLM`(env, 기본 off) · G2 동의(`personal_consent`) · G3 응급억제 · G4 국외이전(`ALLOW_CROSS_BORDER_PERSONAL` ack / `DOMESTIC_LLM_PROVIDERS`) · G5 관련성 · G6 라벨온리 스캔.
- **관찰성 배지**(2026-06-22): 주입이 일어나면 주입된 밴드("혈압=경고")를 `STOP.personal_injected`로 내려보냄 → 뷰어가 🔐 배지 표시. 미주입이면 빈 리스트(음성 확인). 컴플라이언스 관리방안 = [plan 17](../plan/17-personal-signal-to-llm-compliance.md).

### F. 컴플라이언스 / 가드레일 — `analyzer`·`personalization_safety`·`citation_verifier`
- 공용 `ComplianceAnalyzer`(packages/medical_shared) 규칙 기반 위반 탐지 + RAG 전용 오탐 필터.
- C21 질환명 게이트(종결어미 regex 구멍 보완), C22 거짓안심 백스톱(+골든셋), 면책 보장(예외 시에도 부착).

### G. 이벤트 스토어 / 개선 루프 — `analytics_events`  → [05](05-이벤트-스토어와-개선루프.md)
- **비식별 이벤트 스토어**(migration 015): `emit()` = 화이트리스트 `sanitize()`(라벨·카운트·불리언만, 금지키 구조적 제거), fail-closed, 등록 이벤트명만.
- 진입 `query_received` / 종료 4종(`answer_shown`·`insufficient_evidence`(거절수요)·`emergency_redirect`·`triage_clarify`) / 피드백 `thumbs_up·down`.
- 허브 = **이벤트 스토어(Postgres)**, BI = Metabase/Grafana, 품질 = 골든셋·judge. PostHog는 선택. (rag_queries는 원문 보관=내부 감사용, BI 미사용.)

### H. 명시 피드백 — `response_feedback`  → [06](06-명시-피드백.md)
- 👍/👎 + reason_code(코드만, 자유텍스트 0=비식별). migration 016. `POST /api/rag/feedback`(`rag_routes`), analytics 이벤트 emit.

### I. wraith 호환 / 대화관리 API — `service_routes`·`wraith_sse_adapter`·`rag_history_routes`  → [07](07-wraith호환-대화관리-API.md)
- `POST /api/service/conversations/{graph}` SSE. 우리 이벤트(INFO/EVIDENCE_CHECK/GENERATION/STOP/ERROR) → wraith(SearchResult/PROGRESS/INFO token_usage/STOP) 변환.
- 인용 출처 링크: 문서 `source_url` 우선, 없으면 기관 공식 사이트 폴백(`_SOURCE_URL`). `personal_injected`·`followups`도 STOP에 통과.

### J. 페르소나 테스트 하니스 / 뷰어 — `persona_test_server`  → [03](03-페르소나-테스트-서버.md)
- `test_personas/personas.json` 24종(각자 vitals+PHR+공기질 완비, 결정적 longitudinal: 일별 바이탈 7일~6달·검진 10년·처방 5년).
- 뷰어(localhost:8770): **3분할 반응형**(① 페르소나 ② 개인화 패널: 밴드·결합블록·🔐LLM맥락·차트·검진·처방·프로필 ③ 대화). 인용 `[n]` 클릭 출처 팝업, 순차 문진 버튼, 🔐 방향2 배지.
- `--rag-url` 기본 클라우드 dev. `/preview`(결정적·백엔드 불필요) + `/chat`(클라우드 프록시).

### K. 성능 (2026-06-22 — 체감 ~40s→~8s warm)
- **SSE 연결 즉시 종료**(`service_routes` `Connection: close` + `close_connection=True`): keep-alive+`settimeout(30)`이 STOP 후 30초 유휴 대기를 만들던 **진범** 제거. (서버 generate_response는 ~10s에 완료인데 클라가 ~40s에 STOP 수신하던 문제.)
- **`LLM_REASONING_EFFORT=minimal`**: 첫 토큰 전 추론 12.75s→~1s. gpt-5.4-mini 지원값 minimal/low/medium/high(**none은 400**, fail-safe 강등).
- **DB 후처리 비차단화**: 감사·검수·멀티턴컨텍스트·analytics를 데몬 스레드로(STOP 경로에서 제거).
- **INSUFFICIENT 인용-0건 재생성 생략**: 꼬리 LLM 추가 호출 1회 제거.

## 5. 운영 (배포 / 환경 변수)

- **배포**: `deploy-rag.ps1` → Cloud Run `medical-rag-dev`(asia-northeast3, project medical-compliance-tester). `gcloud builds submit` + `gcloud run deploy`. RUN_MODE=rag, gpt-5.4-mini, `LLM_REASONING_EFFORT=minimal`(스크립트에 영속).

  ```
  gcloud run services update medical-rag-dev --region asia-northeast3 \
    --update-env-vars PERSONAL_SIGNAL_TO_LLM=on,ALLOW_CROSS_BORDER_PERSONAL=on
  ```
- 주요 env: `RETRIEVAL_GATE_ENFORCE`(근거부족 차단), `RAG_GUARDRAIL_FP_FILTER`, `DOMESTIC_LLM_PROVIDERS`, `OPENAI_API_KEY`(시크릿).
