진단 리포트 — 수치를 루틴으로 잇는 다리

순환 ③→④의 접점. 이 화면의 유일한 임무는 “내 수치가 이 루틴을 만들었다”를 납득시키는 것이다.

화면 규칙
  • 종합 한 줄은 구간 라벨만. “고혈압이에요” 같은 질환 규정은 어떤 경로로도 금지
  • 결측은 빈칸이 아니라 ‘미측정’으로 명시 — 결측을 정상으로 오독시키지 않는다
  • CTA는 “더 알아보기”가 아니라 행동 시작. 버튼 바로 위에 근거 프리뷰를 붙여 인과를 눈으로 잇는다
  • 응급 라벨이면 이 화면을 렌더하지 않고 즉시 안전 레이어로 전환
데이터
  • GET /diagnosis ← vital_rules.run + wellness_router.worst_band
  • 추천 트랙 산출: 공복혈당 주의 → focus glucose → 트랙 diet
이 화면은 API 확장이 선행돼야 한다 — 현재 구현으로는 렌더 불가. 검수 결과 세 가지가 비어 있다. ① /diagnosis의 item이 {key,label,state}만 반환해 수치·단위·참고범위·검진일·미측정 구분이 없다. ② evidence_phrase가 "{밴드} 구간 기준"이라 “공복혈당 107 mg/dL”을 만들 수 없다. ③ vital_rules에 glucose 신호 자체가 없다(혈압·BMI·심박·산소·체온만). → 선행 작업: items에 value·unit·ref·checked_on·missing 추가 · evidence_phrase를 항목명+수치 템플릿으로 · glucose 밴드 신설. 이 셋이 없으면 불변식 02(근거→행동→완료)가 성립하지 않는다.
안전. 화면에 남는 것은 수치와 구간 라벨뿐이다. 해석·판정 문장은 밴드 산출에만 쓰고 사용자에게 보여주지 않는다. 항목 뱃지 어휘는 정상·주의·경고·미측정이고, 밴드 어휘(안정)와 섞지 않는다.

불변식 01

완료 버튼은 언제나 엄지 안에

390×844 기준 완료 버튼 하단 y ≤ 480px. 배너가 추가되든 코치 메시지가 길어지든, 밀려나는 것은 아래 섹션이지 버튼이 아니다.

불변식 02

근거 → 행동 → 완료는 한 눈에

이 세 요소가 함께 보여야 “내 수치가 이 행동을 만들었다”가 성립한다. 좁은 화면 축약 순서에서도 마지막까지 남긴다.

불변식 03

1탭으로 끝난다

확인 다이얼로그·수치 입력·스와이프 없음. 되돌리기는 완료 후 같은 자리의 버튼으로 제공한다.

원칙 04

상태는 서버가 정한다

S0~S14 판정, KST 날짜, 주차 번호, 스트릭 전부 서버가 확정해 today.state로 내려준다. 프론트가 자체 판정하면 기기 시계·타임존에서 갈라진다.

원칙 05

개인화는 fail-closed, 행동은 fail-open

밴드를 못 구하면 근거칩을 숨기고 일반 루틴으로 계속한다. 개인화 실패가 루틴 자체를 멈추게 하지 않는다.

원칙 06

미실천은 색으로 처벌하지 않는다

레드는 경고·응급 밴드 전용. 미실천의 유일한 표현은 회색 --miss + ‘–’ 글리프다.
