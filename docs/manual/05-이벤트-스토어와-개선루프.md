# 05. 이벤트 스토어와 개선 루프

대화 1턴마다 '무슨 일이 얼마나'를 **비식별**로 기록해, 행동분석·개선 백로그의 단일 허브로 쓴다.

- 코드: [`analytics_events.py`](../../analytics_events.py)
- 스키마: `migrations/015_analytics_events.sql`
- 정본(온톨로지): [`docs/ontology/feedback-ontology.ttl`](../ontology/feedback-ontology.ttl) · 그림 `feedback-loop.png`
- 테스트: `tests/test_analytics_events.py`

## 이벤트 스토어 = 우리 DB(Postgres) 한 곳

```
대화 → 이벤트 스토어(analytics_events, rag_queries 감사 확장) → 개선 백로그 → 골든셋 게이트 → 배포 → 대화
                         ▲                          ▲
                  품질·평가(골든셋·judge)        BI(Metabase/Grafana, 우리 DB 위)
```

- **BI는 `analytics_events`만 조회.** 원문을 보유한 `rag_queries`는 내부 감사용(미조회).
- **PostHog는 선택**(나중·self-hosted·비식별). 지금은 우리 DB + 경량 BI로 충분.

## emit API

```python
import analytics_events as ae
ae.emit("answer_shown", conversation_id="c1", rag_query_id="rq1",
        intent="symptom_triage", gate_decision="PASS", citations_count=3,
        latency_ms=1200, is_followup=True, refusal=False)
```

- 등록된 `EVENT_NAMES`만 적재(그 외 → 무시).
- `sanitize()` 화이트리스트가 **라벨·카운트·불리언만** 통과. 원문·원시값·진단명을 실수로 넘겨도
  컬럼이 없어 저장되지 않는다(**구조적 비식별, E2**).
- fail-closed·비차단: 적재 실패는 응답 생성을 막지 않는다.

## 이벤트 종류

| event_name | 시점 |
|---|---|
| `query_received` | 진입(분류 직후) — 퍼널 분모 |
| `answer_shown` | 정상 답변 |
| `insufficient_evidence` | 근거부족(refusal=1, 거절수요 E4) |
| `emergency_redirect` | 응급 안내 |
| `triage_clarify` | 비의료/모호 되묻기 |
| `thumbs_up` / `thumbs_down` | 명시 피드백(06 참고) |

→ 턴마다 진입(query_received) + 종료(나머지 1건). 퍼널·이탈·거절수요율을 SQL로 산출.

## 허용 차원(deidProps)

라벨: `intent·primary_domain·risk_level·guardrail_action·gate_decision·evidence_quality`
카운트: `citations_count·latency_ms`
불리언: `is_followup·had_personal_block·gave_referral·refusal·emergency`

**금지**: 질의 원문·원시 측정값·진단명·검진 라벨·PII·대화 자유텍스트.

## 배선(generate_response)

4종 STOP 지점에서 `rag_engine._emit_analytics`가 classification에서 intent·도메인·위험도만
뽑아 emit. `had_personal_block`은 개인화 블록 실제 주입 여부를 정확히 반영.

## 개선 루프 공리(E1~E7)

| ID | 규칙 |
|---|---|
| E1 | 피드백은 민감 → 동의·마스킹·국내저장 |
| E2 | 이벤트는 이벤트 스토어(국내)에 비식별만. 원문·원시값·진단명·PII 금지 |
| E3 | 개선 항목은 **골든셋 게이트 통과 시에만 배포**(안전 회귀 0) |
| E4 | 거절수요 = '원했으나 합법적으로 못 준' = KB확장·표현개선 1급 입력 |
| E5 | 자동 추출 피드백은 사람 검수 경유 |
| E6 | 매 턴 응급 재평가·안전 불변식 항상 유지 |
| E7 | A/B는 안전 동등성 전제 |
