**파트너 전달 사항:** PROGRESS strid 3종을 단계 인디케이터에 매핑해 달라. display_message는 서버 제안 문구이며 프론트 자체 문구 사용 가능.

## 2. 인용·출처 표기 — ✅ 대체로 맞음 + 🔴 논의 2건

시안(260618 검토 섹션, ChatGPT/Gemini 벤치마크 포함):
- 본문 **넘버링 인용 [1][2]**, 탭 → 출처 페이지 이동. **URL 없으면 그레이(이동 불가)**
- 출처 칩: **1개면 탭 시 바로 웹**, **2개 이상이면 "출처 +N" 칩 → 출처 바텀시트**
- 바텀시트 항목: 제목 + 디스크립션 **최대 2줄 말줄임**, 이후 말줄임표
- 인앱 브라우저로 출처 열람

우리 계약(코드 확정, `wraith_sse_adapter.chunk_to_search_result`):
- 본문 [N] 인용 마커: `_extract_citations`·`_validate_and_fix_citations`로 검증됨 → 넘버링 계약 ✅
- SearchResult 필드: `title`·`url`(문서 source_url 우선, 없으면 기관 사이트 폴백)·`snippet`(200자)·`source`(표시명)·`display_link` → 제목+설명 2줄+링크 ✅
- URL 폴백 정책 주의: 우리는 빈 URL이어도 **기관 공식 사이트로 폴백**해 링크를 보장 — 시안의 "그레이(이동 불가)" 상태는 우리 데이터로는 거의 발생 안 함. 폴백 링크는 원문 아님 → **원문 URL 채우기(D1, kb ingest source_url)가 품질 포인트**

**🔴 논의 1 — 출처 예시가 영문(Mayo Clinic 등):** 우리 KB는 한국 공식 출처 우선(의료법 정합, doc 25). 시안 예시가 Mayo/해외 웹인 것은 벤치마크 캡처로 보이나, **실데이터는 KDCA·식약처 등 한국 기관이 주**라는 점을 파트너와 정렬 필요(출처 표시명·favicon 처리 포함).
**🔴 논의 2 — 바텀시트 스펙 "논의중":** 필드 계약(제목/설명/URL/기관명)을 우리 SearchResult 필드로 고정 제안하면 논의를 닫을 수 있음.
