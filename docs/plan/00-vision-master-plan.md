## 1. 비전

> **"당신의 몸과 집과 기록을 아는, 그러나 절대 의사 행세를 하지 않는 건강정보 파트너."**
> 모든 답변은 공인 출처를 인용하고, 모든 개인화는 동의 위에서 이루어지며, 모든 판단은 의료진에게 연결한다.

**"GPT/Gemini보다 낫다"의 정의**: 모델 성능이 아니라 ① 동의 기반 개인 종단 컨텍스트(생체신호·PHR·환경), ② 한국 권위 출처 인용의 *결정적 검증*(확률적 언급이 아님), ③ 의료법 컴플라이언스의 아키텍처 강제, ④ 감사 가능성(B2B 진입권). 이 네 가지에서 이긴다.

**대원칙 (전 기능 공통)**:
- **P1**: 개인 데이터 해석은 결정적 규칙 엔진만, LLM은 서술만. LLM에는 원시값이 아닌 가명화·최소화된 findings만 전달 (`[R#]` 인용, KB 인용 `[E#]`과 분리).
- **P2**: 안심 단정 금지. 보수(위험) 방향 단정만 허용 — 단, 소비자 센서값은 재측정 확인 후에만 EMERGENCY (레드팀 #4 반영).
- **P3**: deny-by-default 관할 기능 플래그. 규제 검토를 통과한 (관할, 기능)만 ON.
- **P4**: 본문 적재는 PD/KOGL-1/CC BY 라이선스만. NC·ND는 메타데이터+딥링크.
- **P5**: 멱등·additive 변경, strangler 전환, 운영형 인프라 추가 금지(자체 MQTT·FHIR 서버·Kafka·K8s).
- **P6 (신설, 레드팀 반영)**: **규제 확인이 기능 개발의 선행조건.** 서면 확인 없는 회색지대 기능은 만들지 않는다 — 역순은 매몰비용 제조기다.

## 2. 레드팀 반영 — 확정 결정사항

검토([03-review.md](03-review.md))의 치명 결함 10건에 대한 결정:

| # | 결함 | 결정 |
|---|------|------|
| 1 | 마이헬스웨이 연동 자격 미검증 | Phase 0에 **자격 조사·신청 착수**(코드 아님). 폴백 = 검진결과 업로드/수동 입력을 플랜 A'로 승격. ISMS-P 일정·비용을 로드맵에 계상 |
| 2 | "범위 대조 ≠ 진단" 논증 취약 | **식약처 서면 확인이 해당 기능의 출시 게이트.** 회신 전에는 질병 분류명 매핑 금지 — "공인 기준치(예: 140/90) 인용 + 사용자 수치 병기"의 보수 표현만 |
| 3 | "DUR 미등재" = 묵시적 안전 보증 | **템플릿 비대칭 확정**: '등재 있음'만 출력 가능. '등재 없음'은 출력 금지("이 목록만으로 안전을 판단할 수 없습니다" 고정 문구). 약사법 자문 1회가 DUR 기능 게이트 |
| 4 | 소비자 센서 + 과소경고 금지 = 119 폭주 | EMERGENCY 2단계 확인 명문화: (a) 의료기기 인증 기기 출처 또는 (b) 재측정 프로토콜 통과 후. **false alarm rate를 recall과 동급의 출시 게이트 지표로** |
| 5 | 보호자·아동 데이터 동의 부재 | v1 정책: **"성인 본인 데이터만."** 보호자 모드(시나리오 1·3)는 대리 동의·계정 모델 법적 설계 완료 후 별도 Phase |
| 6 | 모바일 앱 공수 누락 | Phase 0은 **웹 수동 입력만**. HealthKit/Health Connect는 Phase 1로 이동(앱 공수 별도 계상). 최종 사용자 토큰 인증(신뢰헤더 아님)을 Phase 0 설계 항목으로 |
| 7 | "밴딩=비식별" 법적 오인 | 용어 전면 교체: '비식별' → **'가명화·최소화'**(여전히 민감정보). 국외 LLM 전송 비동의 사용자의 **비개인화 모드 폴백**을 제품 스펙으로. 감사 findings 보존 기간·접근 통제 정의 |
| 8 | 미국 진출 논리 자기 파괴 | 글로벌 순서 수정: **한국 → 일본(규제 명문화·제품 문법 이식성) → 영어권은 'KB 파일럿'으로 격하.** 미국 정식 진출은 빅테크(OS 레벨 Health+AI) 대비 차별화 가설 검증을 전제조건으로 |
| 9 | 수익모델·비용 부재 | Phase 0 산출물에 **1페이지 경제성 모델**(쿼리당 원가, 사용자당 스토리지, 고정비) + 과금 가설(B2C 구독 vs B2B2C) 포함 |
| 10 | 사고 대응·보험 부재 | 출시 게이트에 **E&O/배상책임보험 + adverse event 절차 + 온콜 정의** 추가 |

문서 간 모순 해소:
- **팀 가정**: 현 1~3인 기준으로 Phase 0 설계. 02의 11명 조직은 "자금 확보 시 목표 조직도"로 격하.
- **골든셋**: 250문항으로 시작(01 안), 위촉의사 1인 자문. 500문항·리뷰보드 3~5인은 Phase 1 확장 목표.
- **Phase 0 범위**: 아래 §4의 "세로 슬라이스" 단일안으로 통일 (01의 생체신호 ingest ∧ 02의 참조범위 KB의 교집합, 공기질·IoT·PHR 제외).
- **규칙 엔진 통합 스펙**: `vital_reference_ranges`(데이터 — 신호×연령대×로케일×출처버전 lookup 테이블)와 `vital_rules`(로직 — findings 생성 엔진)는 **한 모듈의 두 층**. 엔진이 reference 테이블을 조회해 findings를 산출한다. 위치: `packages/medical_shared/vital_rules`.
- **IoT**: 제휴 센서 확정 전 MQTT 인프라 보류. 제조사 클라우드 API 폴링이 기본 경로(01 본문 안).
- **멀티턴**: Phase 1 (0-3개월에는 설계 문서만).
- **두 번째 리전**: 12개월 내 동결. 글로벌 가설은 "단일(서울) 리전 + 영어 KB 파일럿"으로만 검증.

## 3. 목표 아키텍처 (요약 — 상세는 01 문서)

```
[웹 수동입력(P0) → 앱 HealthKit/HC(P1) → 마이헬스웨이(자격 취득 후) → IoT(제휴 후)]
        ↓ (사용자 토큰 인증 + 동의 게이트)
[Ingest 서비스 (FastAPI, 신규)] — LOINC/UCUM 정규화, 멱등 수신
        ↓
[개인 컨텍스트 스토어 — Cloud SQL personal.* 스키마, 서울 리전 고정]
  phr_observations(월별 파티션) · user_health_snapshot · consent_ledger(append-only) · personal_audit_log
        ↓
[규칙 엔진 vital_rules — reference 테이블 lookup → findings(출처·버전 포함)]
  EMERGENCY는 2단계 확인(인증기기 or 재측정) 후 LLM 미경유 고정 템플릿(119) 즉시 응답
        ↓
[기존 RAG 파이프라인 확장 — Evidence Pack에 personal_context(가명화 findings) 주입]
  생성 → [E#]/[R#] 인용 검증 → 가드레일 → 리뷰 큐 → 감사(rag_queries + consent_ref + rule_version)
        ↓
[관할 기능 플래그 jurisdiction_features — deny-by-default, 규제 검토 승인 흔적 필수]
```

- 기존 자산은 유지+확장(파이프라인·Evidence Pack·hybrid search·마이그레이션 규율). `rag_server.py`(stdlib)는 스트랭글러로 단계 교체 — 신규 ingest만 FastAPI로 시작, RAG 본체 전환은 Phase 1.
- 저장: Cloud SQL PG15 파티셔닝(Timescale은 Cloud SQL 미지원으로 보류, BigQuery는 90일+ 콜드 계층만).
- 시계열 볼륨은 **수집 화이트리스트 확정 후 재추정**(레드팀 Should-fix #1 — 웨어러블 연속 신호 포함 여부가 지배 변수).

## 4. 로드맵

### Phase 0 (0–3개월) — "규제 확인 + 가장 좁은 세로 슬라이스"

**트랙 A: 규제·사업 (코드보다 먼저, 병렬 진행)**
1. 식약처 민원 질의/규제 자문: "공인 기준치 인용 표시"와 레드플래그 문구의 웰니스 해당성 **서면 확인** → 이 결과가 제품 문구 수위를 결정
2. 약사법 자문: DUR 등재사실 표시의 경계 (DUR 기능 게이트)
3. 마이헬스웨이 활용기관 요건·리드타임·ISMS-P 필요 여부 조사, 가능하면 신청 착수
4. 1페이지 경제성 모델 + 과금 가설 + **명시적 동결 목록**(멀티리전·BGE-M3 전환·미국 출시·B2B·IoT 제휴 = 6개월 내 하지 않음)
5. E&O/배상책임보험 견적, adverse event 절차 초안, 온콜 정의

**트랙 B: 제품 (세로 슬라이스 하나)**
1. `consent_ledger` + 동의 UI/게이트 + 철회 즉시 전파(캐시 무효화 이벤트) — "성인 본인 데이터만" 정책 명문화
2. 최종 사용자 토큰 인증 설계·구현 (신뢰헤더는 서버 간 전용으로 유지)
3. `ingest_server.py`(FastAPI, 신규 Cloud Run 서비스): **웹 수동 입력 혈압 1종**만 — LOINC/UCUM 검증, 멱등 수신
4. `vital_rules` v0.1: 혈압 규칙 ~5개 (reference 테이블 + findings 엔진, 전 규칙 공식 출처 명기, 재측정 프로토콜 포함, 단위테스트 100%)
5. Evidence Pack `personal_context` 주입 + `[R#]` 인용 검증 + 가드레일 확장 — KR 플래그만 ON
6. **골든 평가셋 250문항**(비개인화 200 + 개인화 50) + CI 회귀 게이트 + false alarm rate 지표 — 위촉의사 1인 자문
7. 감사 확장: `consent_ref`/`rule_version`/`personal_context_hash` 컬럼

**Phase 0 종료 게이트**: "혈압을 입력한 사용자의 질문에, 규칙 엔진 findings가 주입된 인용 답변이 비개인화 답변보다 골든셋에서 우월한가?" — **이 가설이 깨지면 Phase 1 범위를 재설계한다.**

### Phase 1 (3–6개월) — "수집원 확장 + 본체 현대화"
- 모바일 앱(HealthKit/Health Connect 배치 동기화) — 공수 별도 계상, 스토어 심사 리드타임 포함
- 신호 확장: 체온·SpO2 (기기 등급별 규칙 분리), 공기질은 에어코리아 API(실외)부터 — 실내 IoT는 제휴 확정 시
- 마이헬스웨이: 자격 진행 상황에 따라 연동 착수 또는 폴백(검진결과 업로드) 출시
- DUR 교차조회 (약사법 자문 통과 후, 비대칭 템플릿)
- RAG 서비스 FastAPI 전환 완료, 멀티턴 문맥화, Kiwi 형태소 보강, 피드백 수집 배선
- 골든셋 500문항 확장, 리뷰보드 2~3인
- 식약처 웰니스 적합성 문서(Intended Use Statement) 확정 — 리포 버전 관리

### Phase 2 (6–12개월) — "검증된 것만 확장"
- 보호자 모드 법적 설계(대리 동의·계정 모델) → 시나리오 1·3 해금
- 영어 KB 파일럿(MedlinePlus/CDC PD 콘텐츠) — 단일 리전에서, 일본 시장 조사 병행
- BGE-M3 dual_indexing→shadow_eval (골든셋 향상 입증 시에만 전환)
- 학습형 리랭커 (동일 조건)
- B2B 파일럿 탐색 (감사 가능성 + 보험 + AE 절차가 세일즈 전제)
- SaMD 전환 타당성 평가 — 결정적 규칙 엔진·감사·골든셋이 인허가 기술문서 자산

### KPI (Phase 0 기준선 → Phase 1 목표)
- claim 인용 커버리지 ≥98% · 금지표현 출고 0건 · 골든셋 근거일치율 ≥90%
- 응급 게이트: 평가셋 recall 100% **+ 운영 false alarm rate** (실트래픽 표본 검수 병행 — 자기 평가셋 100%는 안전 보증이 아님)
- `insufficient` 비율 기준선 측정 → 30% 감소
- 개인화 답변의 비개인화 대비 우월성 (골든셋 paired 비교)
- 콜드스타트: 가입→첫 데이터 입력 전환율 (Day 1 경험 설계 포함)

## 5. 데이터 확장 계획 (요약 — 상세는 02 §4)

- **출처 티어링**: T1 한국 공공(KOGL-1: KDCA·MFDS/DUR·HIRA·NEMC·에어코리아) → T2 학회 지침(제휴 필요 — 실패 대비: 기준 *수치*의 사실정보 인용은 저작권 검토로 플랜 B) → T3 글로벌 PD(MedlinePlus·CDC·DailyMed·openFDA) → T4 라이선스 주의(WHO NC·NICE·Cochrane — 메타데이터+링크만).
- **참조범위 KB**(`vital_reference_ranges`): 신호×연령대×로케일×출처버전 구조화 테이블. **LLM이 기준값을 생성하지 못하게 하는 것이 환각 방어의 핵심.** 혈압(KSH 2022/ACC-AHA 2017 로케일 분리)부터.
- **갱신**: DUR 주간 / 감염병 일간~주간 / 본문 분기(해시 비교) / 지침 버전 고정+발효일 관리(구버전 인용 재현 = 감사 요건).
- **수요 주도 수집**: 기존 gap 루프(`rag_gap_analysis.py`)에 컨텍스트 타입 차원 추가 → 로케일별 분리 집계로 글로벌 KB 투자 우선순위 결정.
- **다국어**: "로케일 우선, 번역은 최후." 영어권은 PD 원문 별도 KB. BGE-M3 교차언어 검색은 shadow eval 통과 후.
- **스트레스/HRV**: 공인 참조범위 없음 → 용도 정의 전까지 **수집 자체 보류** (최소수집 원칙).

## 6. 리스크 등록부 (Top 8)

| 리스크 | 완화 |
|--------|------|
| 식약처가 "범위 대조"를 의료기기로 판단 | 서면 확인 선행(P6), 보수 문구 폴백 준비 |
| 마이헬스웨이 자격 미취득/지연 | 폴백 플랜 A'(업로드·수동입력)로 가치 제안 유지 |
