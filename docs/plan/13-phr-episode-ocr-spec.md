# PHR 비검진군 + OCR (구현 스펙) — 6소스 커버리지 완성

> 작성: 2026-06-20 · [10-data-utilization-matrix.md](10-data-utilization-matrix.md) §9 잔여(질병이력·가족력·암검진 갭·처방·진료 + OCR)를 구현 스펙으로 전개.
> 4관점 4회차(데이터=비검진 활용 / 아키텍트=레코드·민감도·OCR게이트 / 비평가=민감정보·오추출 / 기획자=종합). 웹 검증(국가암검진).
> 대상 코드: `vital_input.py`(PHR 원문 V1), `pii_masker.py`, `rag_engine.py`(인용검증), `citation_verifier.py`, `migrations/`. **설계만 — 코드 미수정.**
> **이 문서로 6개 데이터 소스(혈압기·체중계·Vital·워치·PHR검진·PHR비검진+OCR) 전체가 활용 스펙을 갖춘다.**

## 0. 한 줄 결론 (또 한 번의 재구성)

비평가 적발: 세 문서의 안전 서사가 **검진수치 모델(밴드·라벨·과거시제)을 비검진 민감군에 그대로 일반화**한 것이 단일 맹점. 그러나 **비검진 민감군은 라벨 자체가 흉기** — "주의 밴드"는 중립이지만 "우울증 이력"은 라벨이 곧 낙인이다. → 정직한 해법: **활용 ≠ 표면화.** 민감 PHR(정신건강·암·감염병 + 정신과 약물계열)은 *출력에 절대 안 띄우고 내부 톤 조정 신호로만* 활용한다(= 설계된 비활용, 10이 타이핑·EMERGENCY에 적용한 영구 Lv0의 확장). 이로써 "고아 0/다 활용" 강박이 만드는 사고를 차단하면서도 "활용"은 유지한다. 비검진군 위험축은 검진수치와 다르다: **"원시값 vs 라벨"이 아니라 "과거 사건의 현재 단정 + 식별성 + 심리적 위해".**

## 1. 비검진군 공통 골격 (데이터분석가)

검진수치·디바이스와 구별되는 비검진 5종 횡단 규율:

1. **과거시제 절대화** — "이력이 확인됩니다"(과거) ✅ / "있으십니다"(현재) ❌. PHR은 현재 상태를 모른다(관해·완치·중단 불가지).
2. **추상화 계층** — 약물=ATC L3 약리군, 진단=질환 클래스, 기관=기관 클래스, 가족=관계 차수(1도/2도). **개별 식별자(약물명·진단명·기관명·친족 특정)는 전부 비노출**(§4 raw_sensitive).
3. **민감군 4영역 차단** — 정신건강·암·감염병(C형간염·결핵) + 정신/항감염 약물계열(§3).
4. **시간 산술 = 비검진군 저위험·고가치 핵심** — 암검진 수검주기 갭, 마지막 진료 경과기간. 결과·수치 해석 없이 *공개 권장사항과의 시간 차이*만으로 완결(11 §2-B "라벨 없는 활용"의 비검진 실현).
5. **응급/freshness 불변식 상속** — 응급내원은 인구집단 내비게이션만(I5·I7, 개인화발 EMERGENCY 고착 금지), 에피소드 freshness(I10).

## 2. 군별 활용 + 천장 (비평가 제약 반영)

| 군 | 활용 (표면화 가능 부분) | 천장·금지선 |
|---|---|---|
| **질병이력**(비민감: 뇌졸중·심장·고혈압·당뇨·이상지질·COPD) | 과거시제 ack + 4카드 content shaping(indirect 허용) | 현재상태·인과 단정 금지 |
| **질병이력**(민감: 정신·암·C형간염·결핵) | **표면화 0** → §3 내부 톤 신호로만 | direct+세션 재동의 시 외 절대 비표면화 |
| **가족력**(뇌졸중·심장·고혈압·당뇨) | 본인 신호 + 가족력 위험요인 **묶음**(본인 신호 무관 시 단독 표면화 금지) | **운명론 차단 프레임 강제**(§8) |
| **가족력**(암) | 민감 — direct+동의 시만 | 발병연령·관계는 비주입(내부 계산만) |
| **암검진 갭**(위·대장·간·폐·유방·자궁) | **수검주기 갭**(O9) = 최고가치·최저위험 | 결과 판정 금지 + **조건부 환기만**(§8, 단정 금지) |
| **처방이력**(비민감 계열) | 과거 ATC L3 계열 ack(과거시제) | **약물명 0·현재복용 단정 0·인과 0** |
| **처방이력**(정신/항감염 계열) | **표면화 0**(계열명=질환 누설) → 내부 상호작용 체크만 | §3 |
| **진료이력** | 마지막 진료 경과기간(시간 산술) | **내원빈도는 비표면화**(§8, 과해석·무례) → 내부 신호로만 |

| 암종 | 대상 | 주기 | 비고 |
|---|---|---|---|
| 위암 | 만 40+ 남녀 | 2년 | |
| 대장암 | 만 50+ 남녀 | 1년 | 분변잠혈→이상 시 내시경 |
| 간암 | 만 40+ **고위험군** | 6개월 | 간경변·B/C형간염 — **질병이력 교차로 대상 판정** |
| 유방암 | 만 40+ 여성 | 2년 | |
| 자궁경부암 | 만 20+ 여성 | 2년 | |

## 3. 민감군 = 표면화 0, 내부 톤 신호로만 (비평가 §1·§3·§7)

**핵심 재구성**: 정신건강·암·감염병 이력 + 정신과 약물계열은 **출력에 절대 표면화하지 않는다.** "활용"은 내부적으로만:
- **내부 톤 조정**: 민감 이력 존재 시 답변의 안전문구 톤 보수화·의료진 상담 권유 강화 — *그 이력을 언급하지 않고*.
- **내부 상호작용 체크**: 약물계열 상호작용은 내부 검토에만, 출력 비노출.

**왜**: ① 관련성 게이트는 본질적으로 위양성("잠 못 자요"→정신건강 scope→우울증 이력 소환). ② **약물계열만 노출해도 누설**(SSRI 계열 = 우울증 지시). ③ 기기 공유 시 본인 아닌 사람이 화면을 봄.

**결정적 차단 — 비대칭 게이트**(아키텍트):
- 비민감 레코드: `direct OR indirect` (증상 scope 겹침으로 자동 브리징 허용).
- **민감 레코드: `direct AND consent`** — 사용자가 *직접 언급* + 그 세션 *명시 재동의* 둘 다일 때만. indirect 경로는 민감 레코드를 **후보 집합에서 물리 제외**(WHERE에서 `sensitivity='sensitive'` 배제) → LLM이 보는 finding 리스트에 **도달 자체가 0** → 프롬프트 인젝션·환각으로도 복원 불가.
- + **열람주체 게이트**(비평가 §1, 기기 공유): 민감 표면화 직전 열람주체 확인, 불확실 시 폐기(보수 디폴트).

→ 이것은 "방치"가 아니라 **설계된 비활용**. "고아 0/다 활용" 목표를 **PHR 민감군에 한해 명시 폐기**한다(비평가 §7 메타).

## 4. 데이터 모델 — 물리 2테이블 분리 (아키텍트, M5·M4·M3)

09 §5 B저장소의 "약물명 분리"는 주석만 존재 → 첫 생성 시 미반영하면 V1·V2 누출창. **컬럼이 아니라 별도 테이블**로 확정(`SELECT *` 동반유출 방지·분리암호화·국내저장):

```sql
-- migrations/015_personal_record.sql  (012는 검진밴드(11), 013·014 점유 → 015. +_sqlite 짝)
CREATE TABLE personal_record (              -- A. LLM 주입 가능 — 계열·class·정성만
  id, user_id, record_type,                -- diagnosis_hx|family_hx|prescription|screening|treatment
  payload_json,                            -- {value,confidence} 필드구조(M3), 원문 0
  observed_at, sensitivity DEFAULT 'normal',-- 'normal'|'sensitive'
  source_id, confidence DEFAULT 1.0,        -- = payload 필드 최솟값
  user_confirmed INTEGER DEFAULT 0,         -- OCR 초기 0
  consent_scope, created_at, updated_at);
CREATE TABLE personal_record_sensitive (   -- B. LLM 절대 비주입 — 원문·암호화·국내
  record_id PK REFERENCES personal_record(id),
  ciphertext, key_ref, nonce, created_at);  -- 약물명·진단명·기관명·친족명 원문
```

**렌더러 raw_sensitive 미접근 보장(4중)**: ① 주입 경로 DB role에 `personal_record_sensitive` SELECT 권한 부재(GRANT 분리, 코드 실수도 권한거부) ② 주입 자료구조 타입에 `ciphertext`/`record_id` 부재 ③ `record_surface()` 반환은 finding(라벨·class·인용)만, `payload_json` 원문 통과 금지 ④ CI grep=0.

- **M4 가족력**: payload는 `{relation:'first_degree', condition_class, onset_age_band, field_confidence}`(직접관계·질환명 원문은 sensitive행). 암=`sensitivity='sensitive'`.
- **M3 OCR 필드별 confidence**: `payload.field_confidence` 맵(약물명 0.9 vs 용량/단위 0.4), 레코드 confidence=최솟값.
- **consent_ledger**(09 §9-1 신설): `{user_id, data_class, purpose:'local_interpret'|'llm_transfer', cross_border, sensitive_ok, granted_at, revoked_at, version}`. sensitivity 결정은 계열코드→민감집합 멤버십(결정적·fail-closed).

## 5. OCR 확인게이트 상태머신 (아키텍트 + 비평가 §5 최우선)

```
[ocr_extracted] confirmed=0
  ├─ 단위 추출 실패/불일치 ──▶ [blocked]            (11 §6 단위검증, mg/dL↔mmol/L)
  ├─ 저신뢰 필드(conf<τ) ────▶ [needs_field_review]  (필드 개별 재확인)
  └─ 전 필드 고신뢰 ─────────▶ [user_confirmed=1]    (이때만 활용 후보)
```
진입 조건 `user_confirmed=1 AND state∉{blocked,needs_field_review}` **WHERE 절 강제** → 미확인은 SELECT 후보 제외(I4 동형).

**비평가 §5 최우선 — 입력오염 영구화 차단** (입력 1회 무심한 확인 → 무한 활용):
- **진단서 OCR → `diagnosis_hx` 자동생성 금지** — 입력오염+민감정보+영구화+4축 증폭의 최악 교차점. 사람이 항목별 확인한 것만 레코드화.
- **민감 질환·단위 있는 수치·약물 용량 = confidence 무관 "강제 재확인 필드"** — 원클릭 일괄 확인 금지, 항목별 능동 타이핑/선택.
- 확인 통과해도 **민감 분류 유지**(확인이 민감도를 해제하지 않음).

## 6. 비검진 레코드의 [R#] 인용 (밴드 없음)

검진수치는 밴드→ref 인용(11 §5). 비검진은 밴드가 없으니 다른 KB:

| finding | 인용 KB(신규 동반적재) |
|---|---|
| 암검진 갭 | 암검진 권장주기 KB(국가검진 — 일반 사실) |
| 질병이력 shaping / 가족력 묶음 | 질환 일반정보 KB(메커니즘·인구집단) |
| 처방 계열 이력 | 약물 계열 일반정보 KB(계열 일반, 약물명 아님) |
| 진료 프레이밍 | 비-claim(면책·안전안내 — `citation_verifier._NON_CLAIM_RE` 제외) |

배선: finding `cite_doc_id`의 KB 청크를 같은 턴 `chunks`에 강제 동반적재, 누락 시 `_validate_and_fix_citations`(`rag_engine.py:1972`)가 마커 제거→**finding 드롭**(fail-closed). `metadata.cite_doc_id` 불변 별칭 추가(11 §5 동일). I2′ 명사 게이트 동반(condition_class 역매핑 출력도 봉쇄).

## 7. V1 누수 차단 (PHR 원문 — 최고위험, 아키텍트 §5)

`vital_input.py:106-112`가 PHR 자유텍스트 **원문 보존**(`out["phr"]=phr`) → 배선 시 `personal['phr']`를 프롬프트에 append하면 진단명·약물명·정신과력 통째 국외행. **4중 음성 게이트**로 구조 봉쇄:
1. **스키마**: 원문은 `personal_record_sensitive`(§4), 주입 자료구조에 원문 키 타입 부재.
2. **배선**: `out["phr"]` 원문은 `phr_structure()` 구조화 입력으로 1회 소비 후 즉시 폐기. 주입 경로 비전달.
3. **시그니처**: `generate_response`는 `personal_findings`(라벨·class·인용)만, `phr` 원문 파라미터 없음(우회 인자 자체 부재).
4. **런타임 차단 스캐너**: `stream_chat` 직전 system+user_prompt 정규식 스캔 — `pii_masker._HEALTH_SIGNAL_RE` 재사용하되 **차단 모드**(원시 약물명·진단명 패턴 발견 시 throw, 마스킹 무마 금지). + CI: 주입 경로에 `out["phr"]` 직접참조 grep=0.
