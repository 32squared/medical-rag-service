# 21. 종합 비평 · 갭 분석 · 추가 기획 백로그

> 작성: 2026-06-23 · 5역할(기획자·아키텍트·비평가·데이터 아키텍트·UX 디자이너)로 현재 결과 전반을 비평하고 **빠진(추가 기획할) 요소**를 레지스터화.
> 원칙: 안전·컴플라이언스(의료법·비식별 라벨) 유지. **설계·기획만.**

## 0. 한 줄 결론

계획·디자인은 두껍지만(기획 18 · UX 19 · 탐색 20 + 확정 디자인), **실행 가능한 핵심 몇 개가 비어 있다**: ① 선제(Anticipatory) **트리거 엔진** ② **비즈모델·GTM** ③ **코칭 KB·검증** ④ **파트너 통합** ⑤ **실시간 신호 파이프라인**. 컴플라이언스는 계획됐으나 **미검증(법률)**.

## 4. 추가 기획 백로그 (우선순위)

1. **G1 선제 트리거 엔진** — 신호 카탈로그 → 규칙(무엇/언제/빈도캡) → 안전 캘리브레이션 → 데이터모델. *Anticipatory의 심장 — 미루면 컨셉이 공허해진다.*
2. **G2 비즈모델·GTM** — B2B2C 과금 구조·파일럿·경쟁 포지셔닝.
3. **G3 코칭 KB·골든셋** — 콘텐츠 출처·검수 + "거짓안심/효능 0" 회귀.
4. **G5 파트너 통합** — 임베드·SSO·멀티테넌시·화이트라벨.
5. **G6 실시간 신호 파이프라인** — 인입 → 밴드 → 트리거.
6. (G4·G7 컴플라/동의는 [LAUNCH-READINESS](../LAUNCH-READINESS.md)와 연계 — 법률·외부 의존.)

## 5. 갭 심층 설계

### 5.1 G1 — 선제 트리거 엔진 (Anticipatory Engine) · 증분2

> Anticipatory Canvas의 **심장**: "AI가 무엇을·언제·어떻게 **안전하게** 표면화하는가". 결정적 규칙 + 안전 캘리브레이션 + 피로 관리. 미루면 확정한 선제 디자인이 빈 껍데기가 된다.

**5.1.1 신호 카탈로그 (입력 — 전부 비식별 라벨)**
밴드(혈압·혈당·BMI·산소·체온·심박) · 추세(악화/개선/지속) · 웨어러블(수면·활동·걸음·안정시심박, [12](12-wearable-wellness-spec.md)) · 복약 시간 · 검진/예약 일정 · 코칭(체크인 미입력·스트릭) · 환경(공기질). → **원시값·진단명 미사용**(I1/I12).

**5.1.2 트리거 규칙 (결정적 — LLM 아님)**
| 규칙 | 조건 | 표면화(중립) | 우선순위 | 액션 |
|---|---|---|---|---|
| R0 응급 | intent=emergency / 응급밴드 | 119·응급실 | **0(최상)** | 즉시(I7) |
| R1 경고연속 | 경고밴드 N일 연속 | "진료 고려" must-attend | 1 | 병원찾기 |
| R2 복약/검진 | 복약시간·검진 D-7 | 리마인드 | 2 | 알림 |
| R3 추세악화 | 추세=악화 + 주의 | "추세 안내" | 3 | 코칭/안내 |
| R4 코칭재참여 | 체크인 미입력 ≥3일 | 무비난 넛지 | 4 | 체크인 |
| R5 예상질문 | 최근 밴드변화·답변 맥락 | "궁금하실 거예요" | 5 | Q 제시 |

**5.1.3 우선순위·중재** — **한 번에 must-attend 1개**(과부하 금지). 동시 발화 시 위 우선순위로 1개만, 나머지 보류. 응급은 모든 것 위로(I7) + 다른 표면화 차단.

**5.1.4 빈도 캡·피로 관리** — 1일 최대 N개 · 토픽별 쿨다운 · "나중에/스누즈" 존중 · **무시한 항목 반복 금지** · 같은 must-attend는 상태 변화 전까지 1회. (알람 피로 = 선제 모델의 최대 적.)

**5.1.5 안전 캘리브레이션 (가장 중요)**
- **결정적 규칙**(밴드 라벨 기반) — LLM이 "무엇을 띄울지" 단정 안 함.
- 중립 언어 · **"진단 아님" 병기** · 과경고 0 · 거짓안심 0.
- **불확실하면 미표면화**(false alarm보다 침묵이 안전 — 단 **응급은 예외=항상 표면화**).
- 표면화 문구·예상질문도 가드레일·WC-C 통과(화이트리스트 경유).

**5.1.6 데이터 모델**
- `anticipatory_signal`(signal_type, band_label, trend_label, ts) — 비식별
- `surfacing_rule`(rule_id, condition, template, priority, cooldown)
- `surfacing_event`(event_id, rule_id, shown_at, dismissed_bool, action) — 피로캡·분석([015](../../migrations/015_analytics_events.sql) 비식별)

**5.1.7 아키텍처** — **결정적 엔진**: 신호 갱신(이벤트) 또는 앱 오픈(pull) 시 규칙 평가 → **랭킹된 표면화 리스트** → UI가 top 렌더. LLM은 문구 다듬기에만(가드레일 내), 결정엔 미관여. 신호원 = 의료 RAG·방향2(밴드)·코칭([18 §7](18-wellness-coaching.md)).

**5.1.8 남은 결정** — N(빈도캡)·쿨다운 튜닝(피로 vs 누락) · 예상질문: 룰 화이트리스트 vs LLM+가드레일 · 트리거 골든셋(과경고 0·응급 누락 0 회귀).

### 5.2 G2 — 비즈모델 · GTM (기획자) · 증분3

- **모델**: B2B2C — 파트너(건강관리 앱·보험·기업복지·약국체인)가 마이헬스케어를 임베드. **환자 직접 과금은 신중**(의료 신뢰·규제 → B2B 우선).
- **과금**: ① 파트너 SaaS(MAU/seat) ② API 종량(질의·토큰) ③ 프리미엄 코칭 기능.
- **가치 제안(파트너별)**: 건강앱=차별 AI·리텐션 / 보험=건강증진·손해율 / 기업복지=임직원 건강 / 약국=상담 보조.
- **경쟁 포지셔닝**: vs GPT·Gemini(범용 — 한국 의료 컴플라·안전 약함) / vs 국내(굿닥·똑닥=예약·비대면, 삼성헬스=측정, 캐시워크=리워드). **우리 = 의료법 경계 안전 + 개인화 안내 + 선제 코칭** 결합. **해자 = 컴플라 엔진 + 개인화**.
- **GTM**: 파일럿(1~2 파트너·식단 MVP) → 성과(리텐션·핸드오프 수락률·**안전 0사고**) → 확장.
- **가격(초안)**: 파트너 기본료 + MAU 종량 — 시장 검증 필요. **리스크**: 의료 책임 소재(파트너↔우리)·규제·LLM 비용.

### 5.3 G3 — 코칭 KB · 골든셋 (비평·데이터) · 증분4

- **KB 콘텐츠**: 식단/운동/습관 **일반 생활수칙**. 출처 화이트리스트(식약처·보건소·질병청·WHO·전문학회 일반지침) — 의료 KB와 동일 tier·검수 원칙.
- **구조**: 토픽별 권장수칙 + 근거 인용[n] + **금기**(효능표방·치료식 배제, WC-C5 화이트리스트).
- **검수(LAUNCH D)**: 의료진·영양사 검수 → **효능표방·처방성 0** 확인.
- **코칭 골든셋**: "코칭 출력 안전 회귀" — 효능표방 0 · 처방성 0 · 경고밴드 강플랜 0 · 거짓안심 0. 트랙별 위험 시나리오 시드, 의료 골든셋 패턴 재사용.
- **MVP 규모**: 식단 트랙 우선(혈압·혈당·체중 관련 저염·균형 식생활 N항목). **데이터**: coaching KB(`kb_chunks` 구조 재사용 또는 coaching tier 추가).

### 5.4 G5 — 파트너 통합 아키텍처 (아키텍트) · 증분5

- **임베드 모델**: ① iframe/웹뷰 ② SDK(파트너 앱 네이티브) ③ API only(파트너가 UI 구성).
- **인증**: 파트너 **SSO**(OAuth/OIDC) → 우리 세션. 사용자 식별 = 파트너 토큰 → 내부 id 매핑(**PII 최소**).
- **멀티테넌시**: `tenant_id` 분리(설정·KB·브랜딩·플래그·**데이터 격리**).
- **화이트라벨**: 디자인 토큰화(Warm Light 기본, 파트너 컬러·로고 오버라이드).
- **데이터 교환**: 파트너 PHR/측정 → 밴드 산출. **동의·국외이전 게이트** 적용.
- **책임·계약**: 데이터 처리자(수탁) 관계·의료 책임 분담 명확화(법률 의존).
- **API**: REST/SSE(기존 `/api/service/conversations`) + 신규 코칭·선제 엔드포인트 · rate limit · 버저닝.

### 5.5 G6 — 실시간 신호 파이프라인 (데이터·아키) · 증분6

- **인입**: 웨어러블(파트너 앱 push / HealthKit·Google Fit) · PHR(공단·마이데이터) · 측정기기 · 코칭 체크인.
- **처리**: 원시값 → 결정적 밴드/추세(`vital_rules`·`label_trend`) → `anticipatory_signal`(비식별). **원시값은 로컬 처리·LLM 밖**(경계 설계 상속).
- **트리거**: 신호 갱신 시 G1 엔진 평가 → `surfacing_event`. 이벤트 드리븐 + 앱 오픈 pull.
- **실시간성(SLA 차등)**: 웨어러블=배치(주기) · 측정=실시간 · **응급=즉시**.
- **프라이버시**: 원시값 암호화 보관(`personal_record`) · 라벨만 흐름 · 동의 게이트 · 보존정책.
- **아키**: 소스별 수집 어댑터 → 정규화 → 밴드엔진 → signal store → **G1 트리거 엔진** → UI/알림.
