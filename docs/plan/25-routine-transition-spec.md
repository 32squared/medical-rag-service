## A. 제품 정의 — 루틴형 전환 요약과 성공지표

### A-1. 진단과 전환 명제

현황 퍼널은 6,063명 → 업데이트 2,292(37.8%) → 사용 319(5.3%) → 2회 이상 51(0.8%)이고, 세션당 질문은 1.49건이다. 이 수치는 UI 품질의 문제가 아니라 **제품 유형의 문제**다. 정보형(Q&A)의 트리거는 앱 밖(의문 발생 시)에 있고 그 자연빈도는 월 1회 미만이다.

**전환 명제: 트리거를 앱 안으로 옮긴다.**
앱을 여는 이유를 "질문이 생겨서"에서 "오늘 것이 아직 안 끝나서"로 바꾼다. 이를 위해 탭 1번의 정체성을 채팅 입력창에서 **미완결 객체(오늘의 행동 1개, 미완료)** 로 교체한다.

### A-2. 순환 구조와 코드 매핑

| 순환 | 화면/기능 | 구현 지점 |
|---|---|---|
| ① AI 상담(질문 유입) | 상담 탭 | 기존 `POST /chat` |
| ② PHR 연동(개인화 근거) | P1 데이터 연결 | v1은 페르소나 24종(`POST /persona/select`) |
| ③ 상태 진단(수치·판정) | 내 건강 탭 / D1 | 신규 `GET /diagnosis` ← `vital_rules.run` + `wellness_router.worst_band` |
| ④ 루틴 제시(오늘의 행동 1개) | 오늘 탭 히어로 | 신규 `routine_engine` + 기존 `coaching_engine.generate_plan` |

- **⑤→⑥→①**: 체크인 직후 `AskBridge` 질문칩 3개 + 이상변동 칩 + 실패사유 칩 + 주간리포트 질문 3개

## B. 12주 프로그램

### B-1. 단계 정의

| 단계 | 주차 | 목표 | 난이도 | 핵심 메커니즘 |
|---|---|---|---|---|
| 정착기 | 1–2 | 첫 3일 안에 '해냈다' 경험. 성공 기준은 개선이 아니라 **연속 3일 기록** | 최저 — 메인 1개, 30초, 미션은 7일이 아닌 **3일 기준** | 앵커링 + 1탭 즉시 보상 + 3일 배지 예고 |

### B-3. 보조 행동 배정 규칙 (KB 재사용)

보조 행동은 새로 만들지 않고 `coaching_engine.generate_plan(track, intake, band).items`가 반환한 풀에서 주차별 태그 우선순위로 뽑는다.

| 주차 | 보조 슬롯 | 태그 우선순위 | 예시(diet) |
|---|---|---|---|
| 1–2 | 0개 | — | (없음. 정착기는 메인 1개 고정) |
| 3–4 | 0~1개 | 트랙 기본 첫 항목 | `soup_half` |
| 5 | 1개 | diet=`외식` / exercise=`일상` / habit=`수면` | `soup_half`, `ramen_weekly` |
| 6 | 1개 | diet=`짠맛` / exercise=`시작` / habit=`스트레스` | `sauce_dip`, `water_more` |
| 7–10 | 밴드캡까지 | 풀 순환(중복 제거) | `taste_light`, `veggie_add` |
| 11–12 | 1개(유지 루틴으로 지정된 것) | 사용자가 12주차에 고른 항목 | — |

풀이 고갈되면 처음부터 순환한다. 풀이 비면 보조 섹션 자체를 렌더하지 않는다(빈 배열 → 미노출).

### B-4. 개인화 — 밴드가 조정하는 것 / 조정하지 않는 것

**조정하는 것 (밴드 → 항목 상한·배너·미션 형태)**

| 밴드 | 보조 항목 상한 | 확장기 진입 | 배너 | 특례 |
|---|---|---|---|---|
| 안정 | 1~2주 0 → 3~6주 1 → 7~12주 **2** | 3주차 | 없음 | 12주 후 유지 모드 자동 제안 |
| 주의 | 최대 **1** (2개 구간 없음) | **4주차로 1주 지연**(정착기 3주) | 매 주차 상단 "진료와 병행하세요" 상시 | 주간 리포트에 '다음 검진 시 확인할 항목' 블록 |
| 경고 | **0** (12주 내내 메인 1개) | 없음 | 진료 우선 배너 매 주차 최상단 고정 | 6주 스택·8주 챌린지 등 **행동 추가형 미션을 전부 '측정·기록형'으로 치환**. 운동 트랙은 강도 항목 전면 비활성 + clearance 안내 선표시. 게임 요소(스트릭 강조·배지 연출·레벨) 숨김 |

`coaching_engine._select_keys`의 `cap = 2 if band=='경고' else 4`를 커리큘럼에서 **경고=0(보조 없음)** 으로 더 조인다.

**검진 수치 → 트랙·focus 추천 우선순위** (수치는 추천·밴드 산출에만 쓰고 화면에는 밴드와 근거칩만 남긴다)

| 신호 | focus | 트랙(v1 3트랙) |
|---|---|---|
| 수축기/이완기 혈압 주의 구간 | `bp` | diet |
| 공복혈당 주의 구간 | `glucose` | diet |
| BMI·허리둘레 초과 또는 지질(TC/TG/HDL/LDL) 주의 | `weight_activity` | exercise (5~6주 식이 카드 가중) |
| 간기능 항목 주의 | `sleep_stress` | habit (절주 항목 가중 + 보건소 절주 상담 연계) |
| Vital Sign 스트레스·심박 변동 잦음 | `sleep_stress` | habit |
| 처방조제에 유효 투약일수 존재 | (그대로) | **`anchor='med'`** — 단독 트랙이 아니라 선택 트랙의 앵커로 자동 결합 |

**주차 진행 중 밴드 변화**
- 주의 → 경고 진입: 그 주차 항목 상한 즉시 하향 + 진료 우선 배너. **주차 진도는 되감지 않는다**(진도 회수 = 즉시 이탈).
- 경고 → 주의/안정 완화: 다음 주차부터 캡 한 단계 해제. 문구는 "좋아졌다·개선됐다" 금지, **"이번 주부터 항목을 하나 늘려볼 수 있어요"** 라는 행동 문장만.

**조정하지 않는 것**: 포인트·배지·레벨은 실천(체크인)에만 연동한다. 밴드 개선에 연동하면 그 자체가 WC-C1 효능표방이다.

### B-6. 복구·리포트·재진입 메커니즘

**복구** — `coaching_adaptive.coach()` 액션에 1:1 매핑

| 공백 | 액션 | 처리 |
|---|---|---|
| 2~3일 | `reengage_gentle` | "잠깐 쉬어가도 괜찮아요. 오늘 딱 한 가지만" + 1탭 복귀. **진도 되감기 없음** |
| 4~7일 | `reengage_replan` | 항목 1개로 자동 리셋 + 알림 시각 재조정 제안. **12주 주차 진도는 유지** |
| 8일+ | `dormant` | 재초대 주 1회 상한. 죄책감 문구·붉은 경고·카운트다운 금지 |
| 저adherence(<40%) | `simplify` | 항목 축소 + 장벽 태그 질문 |

스트릭 프리즈는 7주차 개방, 주 1회 자동 소모. '돌아온 날' 배지는 **연속 실패 후 복귀했을 때만** 부여한다(연속 성공만 보상하면 한 번 끊긴 사용자는 회복 동기를 잃는다).

**주간 리포트** — 주차 종료 후 첫 진입 시 1회, 4블록
① 이번 주 실천 n/goal + 현재 스트릭 + 획득 배지
② 내 데이터 패턴 — 중립 라벨(안정유지·지속상승·불안정반복)만. "좋아졌다·나빠졌다" 금지
③ 다음 주 테마·미션 예고 (예고 자체가 다음 주 열람 동기)
④ **'이번 주 궁금했던 것' 질문 3개** → 탭하면 상담으로
주의·경고 밴드는 상단 진료 병행 배너 고정. 리포트는 1장 카드로 저장되어 11주차 진료 준비 시트로 재사용된다.

**상담 재진입 4지점**
1. 체크인 완료 화면 하단 — 그 주차 테마 질문칩 3개 (예: 3주 "아침과 저녁 기록이 다른 건 왜인가요?", 5주 "회식 자리에서 국물은 왜 자주 언급되나요?", 7주 "며칠 걸렀는데 처음부터 다시 해야 하나요?")
2. 기록값이 내 7일 범위를 벗어난 날 — "오늘은 평소와 달랐어요 — 어떤 이유들이 있을까요?" (판정 아님, 질문 유도)
3. 실패 사유 태그 선택 시 자동 생성 (야근 → "잠이 부족한 날의 생활수칙", 회식 → "외식이 잦을 때의 실천법")
4. 주간 리포트 4번 블록

그리고 **모든 상담 답변 말미에 "이걸 이번 주 행동으로 넣을까요?" 1탭 버튼**을 붙여 ①→④로 되돌린다. 이 버튼이 없으면 상담은 다시 단발 Q&A가 된다.

### C-2. 핵심 플로우 상세 (v1 구현 대상만)

**F1 온보딩 — 결함 수정 3건**
1. 현재 코드는 동의 grant 루프가 실패해도 `onDone()`으로 진행한다 → 필수(`personal_info`) grant 실패 시 **진행 차단 + 재시도**, 실패 지속 시 토큰 폐기 후 처음부터(반쪽 계정 방지).
2. `sel` 하드코딩(`{personal_info:true}`) 제거 → `items`에서 파생(감사 ④ #17).
3. grant는 순차 루프가 아니라 `Promise.allSettled`로 모아 실패 항목을 나열한다.
동의 화면에서 `push`·`phr_link`를 선택 항목 **상단**으로 올리고 루틴 언어로 설명한다 — push: "매일 저녁 오늘의 행동 1개를 알려드려요(21시 이전)", phr_link: "검진 수치로 나에게 맞는 루틴을 정해요".

**F3 진단 리포트** — 상단 종합 한 줄은 "지금은 **주의 구간**으로 보여요"(❌"고혈압이에요"). 항목 카드 3~5개(혈압·공복혈당·지질·간기능·BMI) = 수치 + 구간 라벨 + 참고범위 막대. **결측은 '미측정'으로 명시**하고 빈칸 금지. 하단 CTA는 "더 알아보기"가 아니라 **[이 수치에 맞는 12주 루틴 시작]** 이고 버튼 위에 근거 프리뷰("공복혈당 107 mg/dL → 식단 트랙을 추천해요"). 응급 라벨이면 렌더 중단하고 F20으로 즉시 전환.

**F5 프로그램 배정** — `POST /routine/start`가 (1) 밴드 재산출 (2) `coaching_engine.generate_plan()`으로 보조 풀 확보 (3) `routine_engine`이 12주 전개 (4) `coaching_plan` 1행 + `routine_program` 1행 저장을 한 트랜잭션으로 수행. 알림 시각 기본 20:00, **21:00 이후 선택 불가**(정보통신망법 야간 광고성 전송 제한). 시작 시각이 KST 21:00 이후면 "오늘은 준비만 하고 내일 1일차로 시작할까요?" 선택지를 준다.

**F7 체크인** — 버튼 3개 **[완료] [못했어요] [해당없음]**. 탭 즉시 낙관적 UI → `POST /routine/checkin`. 서버가 KST 날짜를 확정(클라 시계 불신), `UNIQUE(program_id, action_date, item_key)`로 중복 차단, 중복 요청은 409가 아니라 **200 + 기존 레코드(멱등)**.

**F12 주차 전환(lazy)** — 크론 없이 `GET /routine/today` 응답 시점에 계산.
`week_no = floor((today_kst − started_on − paused_days) / 7) + 1`, 1~12로 clamp.
전환 판정: 지난 주 adherence ≥70% → 승급(보조 +1, 밴드캡 이내) / 40~69% → 유지 / <40% → 하향(보조 0). 경고 밴드는 승급 차단. 결과는 `week_state_json`에 기록.

**F20 안전 에스컬레이션** — 전역 레이어. 응급은 전면 모달로 다른 UI 차단(코칭 진입·체크인·상담 전부 차단). 경고 밴드는 코칭을 **끄지 않고** 항목 상한을 0(메인만)으로 낮추고 게임 요소를 숨긴다 — "스트릭 < 안전". 밴드 정상화 시 **자동 재개 금지**, 사용자가 [루틴 다시 시작]을 눌러야 한다.

## D. 화면 IA

### D-1. 왜 채팅 중심을 버리는가

현재 홈 = 채팅 입력창이다. 이 구조는 "물어볼 게 있어야 열 이유"만 준다. 화면을 예쁘게 고쳐도 트리거 빈도는 안 변한다. 바꿔야 할 것은 **탭 1번의 정체성**이다. 채팅은 강등이 아니라 재정의 — 3번 자리로 옮기지만 진입은 오히려 늘어난다. 오늘 탭의 [왜 이 행동인가요?]와 완료 직후 AskBridge가 진입을 만들고, 실행 중에 생긴 의문은 실제로 존재하는 의문이라 전환율이 높다.

병원·약국 찾기는 탭에서 뺀다 — 자연빈도가 정보형 Q&A와 같아 탭 한 칸을 상시 점유할 가치가 없다. `SafetyBanner`의 referral과 상담 답변 CTA에서 진입하는 편이 발견율이 높다.

탭이 4개인 이유: 5개면 한국어 3자 라벨이 잘리고 엄지 도달 정확도가 떨어진다. 3개면 '오늘'과 '프로그램'이 합쳐져 12주 진도가 홈을 침범한다. 4개면 탭 폭 97~120px로 44px 터치 타깃과 3자 라벨이 안전하게 들어간다.

## E. 데이터 모델

### E-1. 기존 자산과의 관계

```
account (account_db)  ── subject_id ─┬─ consent_record (append-only 원장, 진실원천)
                                     ├─ chat_message           (conversation_id = subject_id)
                                     ├─ coaching_session ─ coaching_plan   ← 보조 항목 풀 저장소로 계속 사용
                                     │                     └ coaching_checkin  (레거시, 신규 UI 미사용)
                                     ├─ ★ routine_program ─ ★ routine_checkin
                                     │                     └ ★ routine_report
                                     └─ ★ routine_notify_pref
analytics_events (비식별 라벨/카운트/불리언만)
```

**재사용 결정**
- `coaching_session` + `coaching_plan`: 프로그램당 **1행**을 그대로 생성한다(`target_period='12주'`). `items_json`이 보조 행동 풀, `safety_banner`가 밴드 배너, `compliance_action`이 WC-C 백스톱 결과다. `routine_program.plan_id`가 이를 가리킨다.
- `coaching_checkin`: 스키마 변경 없이 **동결**. 신규 체크인은 `routine_checkin`에만 쓴다(단일 진실원천).
- `analytics_events`: 이벤트명만 추가(024), 컬럼은 기존 화이트리스트 재사용.

**저장 금지 원칙 유지**: 루틴 테이블에는 원시 측정값·진단명을 저장하지 않는다. 사용자가 입력하는 `value`는 선택지 라벨(비슷/높음/낮음, 시각 hh:mm, 태그)만 허용하고, 자유 텍스트·수치는 v1에서 받지 않는다.

| `day_no` | `(today − started_on − paused_days).days + 1` |
| 주차 귀속 | `week_of(action_date) = floor((action_date − started_on).days / 7) + 1` |
| 주차 `done_days` | 그 주차에 `slot='main' AND status='done'`인 **distinct action_date** 수 |
| 주차 `adherence` | `round(done_days / goal_days * 100)`, `status='na'` 인 날은 goal_days에서 차감 |
| 프로그램 `adherence` | 전체 항목 단위 `done / (done+skip)` — na 제외. `coaching_gamification.adherence_rate` 재사용 |
| **스트릭(계정)** | `subject_id`의 `status='done'` distinct 날짜 집합에서 오늘부터 역순. 빠진 날이 `freeze_used_on`이거나 그 주 프리즈 미사용이면 소모 후 계속 |
| `days_since_last` | `today − max(action_date where status='done')` |
| `state` | C-3 우선순위 규칙 |
| 완주 | `day_no > 84` AND `is_completed(done, 84, 70)` |

### E-4. 커리큘럼 상수 (DB 아님 — `routine_engine.py`)


## H. 안전 규칙 — 코딩 체크리스트

감사 ④의 19개 위험을 8대 규칙으로 압축했다. 신규 코드는 **PR 머지 전 이 8개를 전부 통과**해야 한다.

### H-1. 필수 규칙 8

**1. ErrorBoundary 이중 적용 + 부팅 가드**
```js
import { h, render, Fragment, Component } from 'preact';
class Boundary extends Component {
  static getDerivedStateFromError(e){ return { err:e }; }
  componentDidCatch(e, info){ console.error('[boundary]', this.props.name, e, info); }
  render(){
    if (this.state.err) return html`<div class="pad">
      <div class="err">화면을 표시하지 못했습니다.</div>
      <button class="btn ghost" onClick=${()=>this.setState({err:null})}>다시 시도</button>
      ${this.props.onHome ? html`<button class="btn ghost" style="margin-top:8px" onClick=${this.props.onHome}>홈으로</button>` : null}
    </div>`;
    return this.props.children;
  }
}
```
App 전체 + 각 화면 단위로 건다(화면 경계가 있으면 헤더·탭바가 살아남아 탈출 가능). 부팅 직후 `window.addEventListener('error'/'unhandledrejection')` 등록. `#root`에 **정적 로딩 셸**을 HTML로 넣어 '모듈 로드 실패'와 '렌더 실패'를 구분한다.

**2. 단일 fetch 헬퍼 — r.ok → content-type → json try/catch 3단**
```js
async function getJSON(path, opts){
  let res;
  try { res = await api(path, opts); } catch { return { ok:false, kind:'network' }; }
  if (res.status === 401) return { ok:false, kind:'auth' };
  if (res.status === 403) return { ok:false, kind:'consent' };
  if (!res.ok)            return { ok:false, kind:'server', status:res.status,
                                    data: await res.json().catch(()=>null) };
  if (!(res.headers.get('content-type')||'').includes('json')) return { ok:false, kind:'shape' };
  try { return { ok:true, data: await res.json() }; } catch { return { ok:false, kind:'shape' }; }
}
```
화면 코드에서 `.then(r => r.json())`을 직접 쓰지 않는다. **'서버 오류'와 '데이터 없음'을 같은 화면으로 표시하지 않는다.**

**3. keyed 분기 — unkeyed 동일 태그 형제 금지**
```html
<!-- 나쁨: 슬롯이 사라지면 형제가 재사용됨 -->
${card ? html`<div class="card">…</div>` : ''}
${busy ? html`<div class="card">…</div>` : ''}
<!-- 좋음 1: 안정 key -->
${card ? html`<div class="card" key="today-card">…</div>` : null}
<!-- 좋음 2: 슬롯 개수 고정(재매칭 자체가 불가) -->

<!-- 좋음 3: 가변 길이 배열은 전용 컨테이너로 격리 -->
```

index key 금지 — `key=${m.id ?? (m.role+':'+m.ts+':'+m.text.slice(0,24))}`. 시설 행은 `key=${f.id ?? f.name+'|'+f.addr}`, 지도/전화 `<a>`에 각각 `key="map"/"tel"`.

**4. 렌더 직전 정규화 — 원본 응답을 직접 렌더하지 않는다**
```js
function normToday(raw){
  const p = raw?.program ?? null;
  const weeks = Array.isArray(raw?.weeks) ? raw.weeks : [];
  return {
    program: p, week: Number.isFinite(p?.week_no) ? Math.min(Math.max(p.week_no,1),12) : 1,

```
`map` 앞에는 예외 없이 `Array.isArray`. 객체 접근은 `?.`/`??`. 숫자는 `Number.isFinite` + clamp.

**5. 4상태 렌더 + 모든 상태에 헤더**
loading / error(재시도) / empty / data를 명시 렌더하고 **네 상태 전부에 뒤로가기 헤더**를 그린다. 헤더 없는 early return 금지(현재 Settings·Persona가 데드엔드).

**6. 경합·부수효과 가드**
```js
function useLatest(){
  const seq = useRef(0), alive = useRef(true);
  useEffect(() => () => { alive.current = false; }, []);
  return { begin: () => ++seq.current, accept: id => alive.current && id === seq.current };
}
```
비동기 응답에 시퀀스 ref 또는 AbortController + 언마운트 플래그. `setState` 업데이터는 **순수하게** 유지하고 부수효과는 `useEffect`/핸들러로. 중복 전송 가드는 stale closure에 취약한 state 대신 `useRef`. 모든 async 핸들러는 `try/catch/finally`로 감싸고 `finally`에서 busy 해제.

**7. refresh 싱글플라이트 + 토큰 보존**
```js
let refreshing = null;
function refresh(){ if(!refreshing) refreshing = _doRefresh().finally(()=>{refreshing=null;}); return refreshing; }
async function _doRefresh(){
  const t = LS.getJSON(TK); if (!t?.refresh_token) return false;
  let r; try { r = await fetch(BFF+'/auth/refresh', {...}); } catch { return false; }  // 네트워크 실패는 로그아웃 아님
  if (!r.ok) { if (r.status === 401) LS.del(TK); return false; }
  const d = await r.json();
  const cur = LS.getJSON(TK) || t;                    // 저장 직전 최신 스냅샷 재확인
  LS.setJSON(TK, { ...cur, access_token:d.access_token, refresh_token:d.refresh_token });
  return true;
}
```
`bff/app.py`의 refresh는 1회용 회전이다. 병렬 호출 + 스냅샷 덮어쓰기가 만나면 **확정적으로 로그아웃**된다. 홈 1콜(C2) 설계가 이 위험을 구조적으로 줄이지만, 싱글플라이트는 그와 무관하게 필수다.

**8. 브라우저 API는 전부 안전 래퍼**
```js
const mem = new Map();
const LS = {
  get(k){ try { return localStorage.getItem(k); } catch { return mem.get(k) ?? null; } },
  set(k,v){ try { localStorage.setItem(k,v); } catch { mem.set(k,v); } },
  del(k){ try { localStorage.removeItem(k); } catch { mem.delete(k); } },
  getJSON(k){ try { return JSON.parse(LS.get(k) || 'null'); } catch { return null; } },
```

```html
<div class=${'card ' + (on?'on':'')}>        ⭕ 속성값은 표현식 하나로 통째로
```

빈 슬롯은 `null`로 통일(`null/undefined/false/''`는 렌더되지 않음).
