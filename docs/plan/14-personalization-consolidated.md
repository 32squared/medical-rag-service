## 6. 단일 배선점 + P1a 빌드 DAG (아키텍트)

**신호 사망점 = 단일 배선점**: `service_routes.py:85-88`(파싱→감사로그로 종료) → `:144` 호출(5인자)·`rag_engine.py:1126` 시그니처에 개인화 부재. **호출부 1줄(`personal_findings=`) + 시그니처 1파라미터**가 6소스 전체를 켠다.

**P1a 수직 관통 DAG (혈압기 1종)**:
```
[1] C7 bands 구조화(혈압 6밴드) ─ KB본문 불변(build_reference_documents:300은 rule만)
        │
[2] migration 012 (schema_version, +_sqlite)
   ├─[2b] 출력 라벨 사전분리(I12) + C21 명사 게이트   ┐(병렬)
   └─[2c] migration 015(consent C2·measurement C3)    ┘
        │
[3] C14 lookup_band (밴드행 SELECT, fail-closed)
        │
[4] C1 ingest_server (혈압 수신 + device_grade 서명판정 I8) ←[2c]
        │
[5] C15 vital_rules.run → findings (+C18 맥압 파생)
        │
[6] C19 personal_context 주입 + 관련성 게이트 + C22 ref KB 동반적재
        │
[7] ★ service_routes.py:144 + rag_engine.py:1126 시그니처 + EMERGENCY 생략분기(:1159)
        │
[8] C20 차단 스캐너(stream_chat 직전)
        │
[9] 불변식 골든셋: I1·I2·I4·I5 + 종료 게이트
```
병목 체인: `bands → 012 → lookup → run → 주입 → 배선 → 스캐너 → 테스트`. consent/저장소([2c])는 병렬.

**P1a 종료 게이트(4개 동시 참)**: ① `:144`에 personal_findings 실림 ② 혈압 주의구간이 "📋 내 기록 참고"에 **중립 라벨("관리 권장 구간")** + 측정시점 결합 ③ stream_chat 직전 원시값(122·78) 스캔 0 ④ 질환명("고혈압 1기") findings 출고 0.

**P1a 제외(P1b+)**: C5·C6·C8·C9·C16(워치/민감), C11 deny, C12·C13 KB, C17 record_surface, C23 freshness, C24 OCR.
