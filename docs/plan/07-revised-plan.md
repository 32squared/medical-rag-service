## 0. 한 줄 결론

기존 계획은 **"의료법 위반하지 않으면서"** 절반(아키텍처·컴플라이언스·규제 선행 게이트)은 소규모 팀 기준 최상급이다. 그러나 **"고객이 원하는 답변을 줄 수 있는"** 절반 — 답변 유용성의 정의·측정, 사용자/거절 수요 데이터, 그리고 **지속적 데이터 수집 파이프라인** — 이 비어 있다. 본 문서는 이 빈 절반을 채우고 첫 슬라이스를 법적 최난도(개인 vital 해석)에서 최안전·가치검증 우선(비개인화)으로 재배치한다.

## 2. "적극적 자세"의 경성 한계 (D2 안전장치)

"표현으로 방어"는 강력하나 면책문구로 합법화되지 않는 선이 있다:

1. **무면허 의료행위(진단·처방 단정)는 디스클레이머 무관 위법.** "당신은 ○○병", "○○약 드세요"는 표현으로 못 피한다.
2. **B2B2C에서 파트너 앱이 공동 책임.** "적극적"의 실제 상한 = ① 의료법 경성 한계 ② 파트너 위험 수용도, **둘 중 낮은 쪽.**
3. **합법적으로 적극적인 유일한 경로** = 진단단정+면책이 아니라 **`거절(insufficient) → 길안내 + 공인정보 최대 인용`** 전환. 욕구 충족과 합법성을 동시에 잡는다.

## 3. 비평 요약 (3관점)

### 비평가 — 구멍
- "고객이 원하는 답변"이 측정 대상이 아님(KPI에 유용성/만족/거절률 없음).
- 거절 수요(refusal-demand) 신호 미계측 — 이 제품 핵심 긴장의 유일한 데이터.
- 첫 슬라이스 자기모순(법적 최난도를 맨 앞) → D3로 해소.
- 식약처 회신 지연 시 결정 트리 부재 → D4로 해소.
- 국외이전(LLM) 동의 과소평가(가명정보도 개인정보).
- 임상 거버넌스 얇음(위촉의사 1인).

### 기획자 — 범위·순서
- 고변동 베팅(개인화>비개인화 가설)을 맨 앞에 둠 → D3로 디리스킹.
- 사용자 리서치 0건. 수익모델 1쪽 TODO. 1~3인 과적재.

### 아키텍트 — 구조
- 강점: 결정적 규칙엔진·인용분리·감사 구조가 법적 제약과 정합(유지).
- 확인 필요: 인용 검증의 "결정적" 실구현(LLM 자기인용 의존이면 결정적 아님).
- 멀티턴 재작성의 안전 누수(후속처럼 들리는 새 응급) — 매 턴 재평가 불변식 + 테스트 필요.
- 실시간 피드 staleness→억제 정책 명시 필요.

## 4. 누락된 핵심 — 데이터 수집 파이프라인 (코드 근거 진단)

**현 실체**: 수집 *스크립트*는 있으나 지속적·자동 수집 *전략*이 없다.

| 문제 | 근거 |
|---|---|
| MFDS 안전성서한 ≈ 0건 | NAT IP 화이트리스트 미등록 → 타임아웃 시 빈 리스트 (`collect_public_kb.py:249,280`) |
| API 키 의존 출처 스킵 | `KDCA_API_KEY`/`DATA_GO_KR_KEY` 미설정 시 빈 결과 (`:480,:671`) |
| 자동 갱신·스케줄러 전무 | Cloud Scheduler/cron 검색 0건. 전부 수동 CLI. `update_frequency`는 메타데이터일 뿐 |
| 해외 출처 수집기 부재 | 라우터는 WHO/CDC/NICE/DailyMed/PubMed로 라우팅(`retrieval_router.py:27`)하나 수집기 없음 → secondary 항상 빈손 |
| 변경감지 재크롤 루프 없음 | `source_checksum`은 INSERT 중복스킵용으로만 사용. 주기 재fetch→해시비교→갱신 미구현 |
| HTML 스크래핑 취약 | 하드코딩 CSS 선택자·`contentsno` ID(`:565`) → 사이트 개편 시 조용히 깨짐 |
| 메타데이터 품질 | ingest 시 `evidence_level="B"` 하드코딩(`:1503`) → freshness·evidence_level 랭킹 인자 잠듦 |

**채워야 할 수집 파이프라인 설계**
1. **스케줄 수집**: Cloud Scheduler → Cloud Run Job(`collect_public_kb`)을 출처별 주기로 — 안전성서한·DUR 주간 / 감염병 일간~주간 / 본문 분기.
2. **변경감지 루프**: 재fetch → `source_checksum` 비교 → 변경분만 재ingest + 구버전 보존(감사 요건) + 발효일·개정일 색인.
3. **막힌 출처 해소**: MFDS NAT IP 등록(또는 공공데이터 API 전환), 운영 API 키 점검.
4. **수집 건전성 모니터링**: 출처별 수집량 급감 알림(스크래핑 깨짐 조기감지).
5. **메타데이터 의무화**: `published_at`/`revised_at`/`evidence_level` 실값.
6. **해외 PD 출처**(Phase 2): CDC/MedlinePlus/DailyMed 수집기 → 라우터 빈손 해소.

## 5. "지금 의료상담 챗봇이 되는가" — 판정

- **정보 안내형 MVP로는 동작**: 비개인화 증상정보·진료과 길안내·응급 트리아지·예방접종·생활관리. 오프라인 골든셋 안전·인용·도달 100%.
- **상담 챗봇으로 신뢰·경쟁하려면 3개 결핍**:
  1. 데이터 신선도(자동 갱신 없음, MFDS 공백)
  2. 멀티턴(설계만, 코드 없음 → 둘째 턴부터 끊김)
  3. 경쟁/유용성 측정(GPT·Gemini 대비, 거절률, 실트래픽 false alarm rate)
- **결론**: "될 수 있는 뼈대"이지 "된 상태"가 아니다.

## 6. 재정의된 로드맵

```
Phase 0  비개인화 경쟁력 + 측정의 빈 절반 + 수집 파이프라인   ← 대부분 자산 존재
Phase 1  개인화(기존 Phase 0 슬라이스 이동) + 본체 현대화
Phase 2  검증된 것만 확장(해외 KB·보호자 모드·BGE-M3)
```

### Phase 0 작업 (비개인화)
**A. 측정 (최우선 — 경쟁 B2B2C라 필수)**
1. 경쟁 벤치마크 골든셋(동일 질문 vs GPT/Gemini: 근거정확성·유용성·거절여부).
2. 거절 수요 계측 — `rag_gap_analysis.py`에 "원했으나 합법적으로 못 준" 신호.
3. KPI에 유용성/만족·거절률 추가.

**B. 표현 방어 + 거절→길안내 (D2 합법 구현체)**
4. 보수표현 사전 + 경성 금지표현(진단단정·처방·"안전합니다") 출고 0 게이트.
5. insufficient → 길안내 전환기(과·준비·공인정보 최대 제공).
6. 표현 수위 버전 정책(식약처 회신 전/후 플래그 전환·감사) → D4.

**C. 자산 마무리**
7. 빈 라우팅 출처 적재 + §4 수집 파이프라인(스케줄·변경감지).
8. 멀티턴 구현([06](06-multiturn-design.md) → 코드).
9. KB 메타데이터(`published_at`/`evidence_level`) 활성화.

**D. B2B2C 거버넌스**
10. 파트너 책임 경계·디스클레이머 노출 요건·감사 export·API SLA.

### Phase 0 종료 게이트 (교체)
기존 "개인화>비개인화" → **"경쟁모델 대비 우월 + 거절률↓ + 안전 100% + 데이터 신선도 보장"**.

### Phase 1 — 개인화 (기존 Phase 0 이동)
consent_ledger → `ingest_server.py`(혈압 1종) → `vital_rules` v0.1 → `personal_context` 주입. 국외이전 별도 동의 + 비개인화 폴백.

## 9. 검증 로그 (2026-06-20 — 코드 확인)

아키텍트 비평의 검증 가능 항목을 코드로 확인한 결과:

### 9.1 인용 검증의 "결정성" — 대체로 사실, 단 의미적 근거는 미검증
- `citation_verifier.verify_citations()`는 **LLM 비의존 규칙 기반**(정규식)이 맞다(`citation_verifier.py:10`). 파이프라인의 **정상 경로와 응급 경로 양쪽에 배선됨**(`medical_rag_pipeline.py:114,136`). 2층 구조: `rag_engine._validate_and_fix_citations`(마커 범위) + `verify_citations`(문장 claim 커버리지). `overall_pass`는 coverage ≥ 0.99 요구(엄격). 금지표현(진단단정·처방·응급안심·과대) 정규식 삭제 동작 + 테스트 9종 존재.
- **갭**: 검증은 ① 인용 마커 존재·범위(E5가 팩 안에 있는가) ② 금지표현까지만 결정적이고, **인용이 실제로 그 문장을 뒷받침하는지(semantic grounding)는 검증하지 않는다**(`:112-121`은 마커 in-range만 확인). 또 claim 탐지가 키워드+종결어미 휴리스틱(`:31-66`)이라 목록 외 표현의 유해 claim은 빠질 수 있음(false negative).
- **함의**: 00 비전의 "한국 권위 출처 인용의 *결정적 검증*(확률적 언급이 아님)" 주장은 *마커 수준*에서 참이나 *의미 수준*에서는 아직 미달. → Phase 0 B군에 **"claim↔근거 의미 일치 검증"**(규칙 강화 또는 검증용 LLM 1콜 게이트)을 추가 항목으로 등록.

### 9.2 멀티턴 — 미구현 확정
- `followup_rewriter.py`·`conversation_context.py` **부재**. `medical_rag_pipeline.py`에 followup/rewrite/last_symptom 배선 **없음**.
- `conversation_serializer.py`·`rag_history_routes.py`·migration `011_conversation_compat`는 **Phoenix 대화 CRUD 호환**(목록·검색·상세)일 뿐, [06](06-multiturn-design.md)의 컨텍스트 이월·질의 재작성과 무관.
- 현재 각 질의는 독립 처리 → 그 자체로 안전하나(매 질의 재분류) "상담 대화"는 둘째 턴부터 끊김. 구현 시 06 §6 안전 불변식의 **테스트 게이트가 선행 조건**(현재는 검증할 코드가 없어 테스트도 없음).

### 9.3 실시간 피드 staleness — 안전하게 처리됨
- `context_feeds.get_context_feeds()`는 TTL 캐시(`:42,167`). 만료 시 동기 재fetch, 실패 시 `None` 반환 → `render_context_for_prompt()`가 `None`을 주입 생략(`:188`). **만료된 데이터를 "오늘"로 제공하는 일이 없음** → 아키텍트 우려 해소. 렌더는 사실+출처만, 행동권고는 KB `[E#]`가 담당(좋은 분리).
- 소소한 점: 실패도 TTL 동안 캐시(`:172`)되어 일시 장애 시 해당 TTL 동안 재시도 안 함(경미). weather/flu/food_poison은 TODO 미구현(`:175`).

### 9.4 매 질의 응급 재평가 — 보장되나 키워드 의존이 안전 급소
- `medical_classifier`는 규칙 기반, 우선순위 crisis > emergency(`:99-106`)로 매 질의 분류. 파이프라인 무상태 → **매 턴 응급 재평가 보장**(안전).
- **단, 응급 탐지가 키워드 매칭(`_KW["emergency"]`)에 의존** → 구어체·오타 응급("숨을 못 쉬겠어" vs "호흡곤란")이 미탐지될 수 있음. 이는 기존 "도달(reach) 문제"의 **안전상 가장 치명적 인스턴스**다. → Phase 0 안전 최우선 항목으로 **응급/위기 키워드의 구어체·동의어 확장 + 응급 전용 골든셋**을 등록(일반 도달 개선보다 우선).
